# Рейтинг курса и повторение старых слов — план реализации

Цель: ученики курса соревнуются **выученными словами**; рейтинг считается точно и не накручивается; старые слова
регулярно возвращаются в повторение, потому что уроки идут через день и каждый урок добавляет новые слова.

Принципы, на которых держится весь план:

1. **Сервер — единственный источник правды.** Клиент сообщает только «что ученик ответил»; уровень карточки, дату
   следующего повторения, очки и место в рейтинге считает сервер. Всё, что посчитано на телефоне, можно подделать.
2. **Очки только за то, что можно проверить.** Шаг вверх — только когда карточке пришло время повторения.
   Повтор раньше срока тренирует, но не двигает уровень и не даёт очков.
3. **Повторять выгоднее, чем листать новое.** Повторение вовремя стоит дороже нового слова.
4. **Рейтинг — это сумма журнала событий, а не счётчик.** Каждое очко — отдельная строка с причиной; рейтинг
   всегда можно пересчитать и проверить.

## Этап 1. Честная интервальная система (SRS на сервере)

### 1.1. Правила уровней

Уровни остаются прежними (`SRSService.ts`), меняется только правило, **когда** шаг растёт.

| Шаг | Уровень | Считается «выученной»? | Следующее повторение |
|---|---|---|---|
| 0 | `new` | нет | сразу |
| 1–2 | `learning` | нет | 1 / 3 дня |
| 3–4 | `young` | **да** | 7 / 14 дней |
| 5+ | `mature` | да (и «выучено надолго») | 30 / 60 дней |

**Выученная карточка = `young` или выше** (шаг ≥ 3). Одно определение для экрана набора, статистики, рейтинга и учителя.
Текущий `selectSetStats` (выучено = «дата повторения в будущем») заменить: сейчас одно правильное нажатие делает
карточку «выученной», а через день она снова выпадает — число скачет.

### 1.2. Когда шаг меняется

| Ситуация | Шаг | Дата повторения |
|---|---|---|
| Новая карточка (шаг 0), правильно | 0 → 1 | +1 день |
| **Время пришло** (`next_review ≤ сейчас`), правильно | +1 | по таблице |
| **Время пришло**, «Уверенно» (только объективная проверка, см. 1.3) | +1 (не +2) | по таблице |
| Время **не пришло**, правильно | **не меняется** | не меняется |
| Ошибка (в любой момент) | −1 (не ниже 0) | сразу «к повторению» |
| «Не знаю» | 0 | сразу |

Следствие: от нуля до `young` минимум 1 + 3 = 4 дня, до `mature` 1 + 3 + 7 + 14 = 25 дней. Пять прогонов подряд
за вечер больше ничего не дают.

Льгота на опоздание и часовые пояса: считать «время пришло», если `next_review ≤ answered_at + 6 часов`
(ученик повторяет вечером накануне — засчитывается).

### 1.3. Какие режимы двигают уровень

| Режим | Как проверяется ответ | Двигает уровень | Очки рейтинга |
|---|---|---|---|
| Тест (4 варианта) | объективно | да | да |
| Собери слово | объективно | да | да |
| «Напиши перевод» / аудио-диктант (если появится ввод) | объективно | да | да, ×1.5 |
| Карточки (самооценка «Не знаю … Уверенно») | ученик сам говорит | да | **нет** |
| Подбор (Match), Аудио-прослушивание | не проверяет знание | нет | нет |

Самооценку нельзя проверить: ученик нажмёт «Уверенно» на всё. Поэтому она двигает его личное расписание,
но очки рейтинга дают только режимы, где сервер знает правильный ответ.

Угадывание в тесте (25%): ошибка отнимает шаг, а очки даются только за повторение вовремя, поэтому случайные
нажатия в среднем уводят карточку вниз. Дополнительно — варианты ответа генерирует сервер (1.4).

### 1.4. Серверная проверка ответа

Клиент больше не присылает «шаг» и «дату» — только факт ответа.

`POST /api/progress?action=answer` (или пакетом `answers`, до 50 за раз, для офлайн-очереди):

```
{ answerId: uuid,            // генерирует клиент — идемпотентность
  cardId, mode,              // 'test' | 'builder' | 'flashcard' | ...
  questionId?,               // для объективных режимов — выдан сервером
  chosen?,                   // выбранный вариант / собранное слово
  selfRating?,               // только для flashcard
  answeredAt, timeSpentMs }
```

- **Объективные режимы:** `GET /api/progress?action=question&cardId=…&mode=test` → сервер выдаёт `questionId`
  (подписанный, живёт 10 минут) и варианты. Правильный ответ сервер знает сам; клиент присылает `chosen`.
  Так нельзя «сказать серверу, что ответил верно» — сервер сверяет сам. Вопросы можно выдавать пачкой на всю сессию,
  чтобы игра не ждала сеть на каждой карточке.
- **Идемпотентность:** `answers.id = answerId` (PK) — повтор запроса из офлайн-очереди не считается дважды.
- **Время ответа (`answeredAt`)** принимается от клиента (для офлайна), но:
  не в будущем (+5 мин допуск), не старше 7 дней, не раньше предыдущего ответа по этой карточке.
  Всё за пределами — ответ сохраняется, но уровень и очки не меняются (флаг `rejected_reason`).
- Сервер в одной транзакции: пишет ответ → пересчитывает `card_progress` по правилам 1.2 → пишет события очков (этап 2).
- В ответе клиенту — новый уровень и дата, чтобы интерфейс сразу обновился.

Офлайн: клиент продолжает показывать прогресс локально (оптимистично), очередь `SyncQueueService` отправляет
ответы пакетом; после ответа сервера локальное состояние заменяется серверным.

## Этап 2. Очки и рейтинг курса

### 2.1. За что очки

| Событие | Очки | Условие |
|---|---|---|
| Новое слово: первый правильный ответ (0 → 1) | +1 | объективный режим |
| **Повторение вовремя**, правильно | **+2** | `was_due`, объективный режим |
| Слово стало выученным (первый переход в `young`) | +3 | один раз за карточку навсегда |
| Слово выучено надолго (первый переход в `mature`) | +5 | один раз за карточку навсегда |
| Ошибка | 0 | очки не отнимаются (отнимается шаг) |

Повтор раньше срока и «Подбор»/«Аудио» — 0 очков.
«Первый переход» фиксируется `first_learned_at`/`first_mature_at` — забыл и выучил заново → уровень вернулся, очков нет.

### 2.2. Журнал очков

```sql
CREATE TABLE score_events (
  id         BIGSERIAL PRIMARY KEY,
  user_id    UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  card_id    UUID NOT NULL REFERENCES cards(id) ON DELETE CASCADE,
  answer_id  UUID NOT NULL REFERENCES answers(id) ON DELETE CASCADE,
  kind       VARCHAR(20) NOT NULL,  -- new | review | learned | mature
  points     SMALLINT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL,  -- = answers.answered_at
  UNIQUE (answer_id, kind)           -- один ответ не даст одно событие дважды
);
CREATE UNIQUE INDEX ON score_events (user_id, card_id, kind) WHERE kind IN ('learned','mature');
CREATE INDEX ON score_events (user_id, created_at);
```

### 2.3. Какие карточки считаются в курсе

Карточка засчитывается в курсе, если её набор — **набор курса**: собственный набор курса учителя или официальный юнит
учебника, открытый в курсе (та же логика, что `courseSetIdsSql` в `api/teacher.js`). Личные наборы ученика не считаются —
иначе можно создать 500 лёгких карточек. Курс определяется в момент запроса рейтинга, а не записи события, поэтому
если учитель открыл юнит позже, очки за него тоже появятся.

Ученик в двух курсах: очки за карточки курса A идут только в рейтинг A. Если один юнит учебника открыт в обоих курсах
(редкий случай) — засчитывается в оба; это допустимо.

### 2.4. Неделя

- Неделя: понедельник 00:00 — воскресенье 23:59:59 **по часовому поясу курса**. Добавить `courses.timezone`
  (по умолчанию пояс учителя из `user_stats.timezone`, сейчас по умолчанию `Asia/Bishkek`).
- Очки недели = `SUM(points)` событий с `created_at` в границах недели по картам курса, для участников `course_members`
  с ролью `student`. Учитель в рейтинге не участвует.
- Ничья: выше тот, кто набрал итоговую сумму раньше (время последнего события).

`GET /api/progress?action=leaderboard&courseId=…&week=current|previous` → места, очки, моё место,
«до следующего места N очков», время до конца недели. Доступ: только участник курса или его учитель.
Кэш на 60 секунд (одна строка на курс+неделю).

### 2.5. Итоги недели (заморозка)

Раз в неделю (понедельник 00:10 по поясу курса, тот же внешний cron, что вызывает `push?action=cron-streak`):

```sql
CREATE TABLE weekly_results (
  course_id  UUID NOT NULL REFERENCES courses(id) ON DELETE CASCADE,
  week_start DATE NOT NULL,
  user_id    UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  place      SMALLINT NOT NULL,
  points     INTEGER NOT NULL,
  reward     INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (course_id, week_start, user_id)
);
```

- Сохраняет итоговую таблицу — «Прошлая неделя» читается отсюда и больше не меняется
  (поздние офлайн-ответы за прошлую неделю в неё не попадут).
- Награда топ-3: +50 / +30 / +20 алмазов и значок. Начисление — вставка в `weekly_results` + `UPDATE users.diamond`
  в одной транзакции; PK не даст выдать дважды при повторном запуске cron.
- Награда только при минимуме активности (например, ≥ 20 очков), иначе в классе из трёх неактивных «победит» тот, у кого 2 очка.

### 2.6. Анти-накрутка — сводка

| Способ накрутки | Защита |
|---|---|
| Прямая запись в БД | Этап 0: строки подключения нет в приложении, пароль сменён |
| Подделать запрос «ответил верно» | Сервер сам сверяет ответ по `questionId` |
| Жать «Уверенно» в карточках | Самооценка не даёт очков |
| Прогонять одни и те же слова много раз | Шаг растёт только когда время пришло |
| Забыть и выучить снова ради очков | `learned`/`mature` — один раз за карточку |
| Создать свой набор из лёгких слов | Считаются только наборы курса |
| Повторить запрос (сеть/очередь) | `answerId` — PK, `UNIQUE (answer_id, kind)` |
| Подделать время ответа | Окно ±: не в будущем, не старше 7 дней, не раньше прошлого ответа |
| Угадывать в тесте | Ошибка отнимает шаг; варианты от сервера |
| Бот, кликающий быстро | Ответ быстрее 600 мс — засчитывается в SRS, но без очков; > 30 ответов в минуту — rate limit 429 |
| Резкий аномальный рост | Мягкий дневной потолок очков в курсе (например, 300); сверх — очки копятся, но в рейтинг идёт потолок. Учителю — пометка «подозрительная активность» |
| Два аккаунта | Рейтинг внутри курса, учитель видит состав и может удалить ученика (`remove-student`) |

## Этап 3. Триггеры, чтобы старые слова возвращались

Уроки через день, интервалы 1 → 3 → 7 → 14 дней: слова каждого урока сами всплывают в дни без уроков.
Задача — чтобы ученик **заметил** это и вернулся.

### 3.1. «Повторение дня» — главное действие на главной

- Первая кнопка под мини-играми, вместо «Учить все карточки»: **«Повторение дня · 14 слов · ~4 мин»**.
- Очередь собирает сервер (`GET /api/progress?action=review-queue&courseId=…`): все слова курса, которым пришло время,
  по всем урокам; сначала самые просроченные; максимум 30 за раз (остальное — «ещё 12» после).
- Режим — объективный (тест / собери слово вперемешку), чтобы шли очки.
- Когда очередь пуста: «Всё повторено ✓ · следующие 8 слов завтра» и кнопка «Учить новый урок».

### 3.2. Мини-игры едят слова «к повторению»

«Быстрый раунд», «Снайпер», «Вспомни забытое» сначала берут слова, которым пришло время, и только если их мало —
случайные. Ученик играет ради алмазов и незаметно повторяет. Правило «шаг только вовремя» работает и здесь.

### 3.3. Видно, что слова «тают»

- У каждого юнита в списке: **«Unit 3 · 6 слов ждут»** (оранжевая метка) и прогресс-бар, который бледнеет у просроченных слов.
- **Угасание:** если слово просрочено дольше своего интервала (было «через 7 дней», прошло 14) — шаг −1 при следующем
  ответе, даже правильном. На экране заранее: «3 слова начинают забываться». Страх потерять выученное — сильнейший триггер.
- В рейтинге рядом с моими очками: «8 слов ждут = до +16 очков».

### 3.4. Разминка перед новым уроком

Когда учитель открывает новый юнит, у ученика при входе в него сначала **«Разминка: 10 слов из прошлых уроков»**
(только если есть слова к повторению), потом новые слова. Кнопка «Пропустить» есть — это подсказка, не запрет.

### 3.5. Серия дней

День засчитывается в серию, только если выполнено «Повторение дня» (или слов к повторению не было).
Сейчас серия растёт от любой активности.
«Заморозка серии» за алмазы (например, 50) — алмазам появляется смысл, пропуск одного дня не обнуляет мотивацию.

### 3.6. Пуш-уведомления (инфраструктура уже есть: `api/push.js`, FCM)

Не больше одного пуша в день, только если «Повторение дня» не сделано:

| Когда | Текст |
|---|---|
| Вечер (время из `notif_hour`) | «14 слов из Unit 3 и Unit 4 пора повторить · 4 минуты» |
| Накануне урока | «Завтра урок — повтори 10 старых слов, чтобы не забыть» |
| Слова начали угасать | «5 слов начинают забываться — спаси их за 2 минуты» |
| Рейтинг, вечер воскресенья | «Ты на 3-м месте, до 2-го — 4 слова. До конца недели 3 часа» |
| Понедельник | «Итоги недели: 3-е место, +20 💎. Новая неделя началась» |

Учитывать настройки `notif_*` пользователя; «тихие часы» 22:00–08:00.

### 3.7. Экран итогов недели

Раз в понедельник при первом входе: место, очки, сколько слов стало выученными, сравнение с прошлой неделей,
награда. Короткий «праздник» + мотивация на новую неделю.

### 3.8. Учитель как триггер

- В статистике курса по каждому ученику: **выучено**, **очки недели**, **просрочено повторений**, дней без повторения.
- Кнопка «Напомнить повторить» — одному ученику или всем с просрочкой (пуш от имени учителя).
- Перед уроком — «Разогрев»: живой тест (уже есть `test_sessions`) автоматически из слов прошлых уроков.
- Переключатель «Рейтинг для учеников» (выкл. — ученики не видят рейтинг; очки всё равно считаются).
