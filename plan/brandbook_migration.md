# План: приведение приложения к брендбуку

Цель — чтобы **внешний вид** каждого экрана и компонента соответствовал [brandbook.md](brandbook.md): цвета, шрифты, размеры, отступы, скругления, иконки, тёмная тема, доступность.

## Главное правило: контент не трогаем

Меняется **только то, как выглядит**. **Не меняется то, что есть на экране:**
- не убираем и не добавляем кнопки, блоки, разделы, вкладки, пункты меню;
- не меняем порядок элементов и структуру экранов (в том числе главной);
- не переписываем тексты (кроме замены эмодзи на иконки);
- не удаляем экраны и данные, даже если они выглядят лишними или выдуманными.

**Исключения — согласованные правки контента** (делаются по плану, этап 4):
- подписи под иконками в панели вкладок (шаг 1.6);
- все тексты интерфейса — на «ты»;
- убрать выдуманные блоки статистики;
- кнопка «Сканировать QR-код» — сделать рабочей.

Остальное, что меняет состав, — в разделе **«Не входит в план»** в конце: это отдельные решения владельца продукта.

**Иконки:** везде lucide, **эмодзи убираем полностью** (заменяем иконками lucide). **Исключения:** нижняя панель вкладок (Главная, Библиотека, Тест, Профиль) остаётся на Ionicons; **флаги языков** (🇬🇧 🇩🇪 …) остаются.

## Как работать с планом
- Шаги идут по порядку: этапы 1–2 (фундамент и компоненты) — раньше экранов, иначе каждый экран придётся переделывать дважды.
- Один шаг = один коммит (не смешивать шаги). В сообщении коммита — номер шага (`Brand 3.2: …`).
- После каждого шага: `npm run brand:check` (шаг 1.1) — число нарушений только уменьшается; экраны проверены в светлой и тёмной теме; **визуальный состав экрана до и после одинаковый** (те же кнопки, тексты, блоки).
- Отмечать `[x]` по мере выполнения.

**Счёт нарушений** в таблицах — сумма: цвета в коде (`'#…'`, `rgba`), `isDark ? …`, размеры шрифта вне шкалы, веса 500/800/900, скругления вне пяти, прозрачности вне трёх ступеней, системные `Alert` для не-опасных сообщений. Отдельно считаются эмодзи и Ionicons вне панели вкладок. Замер на старте — **≈2 330** нарушений по 88 файлам, **55 эмодзи**, **Ionicons в 27 файлах**.

## Этап 3. Экраны

1. обёртка `Screen` + `ScreenHeader` (те же заголовок и действия);

Это замечания из аудита, которые **не делаются** в рамках перевода на брендбук. Каждое — отдельное решение владельца продукта.

| Замечание | Где |
|---|---|
| Упростить главную: одно главное действие, меньше блоков | `HomeScreen.new.tsx` |
| Одна главная кнопка на экранах, где их несколько | разные экраны |
| Формулировки ошибок «что случилось + что сделать» | все экраны |
| Экран «Награды» с выдуманным списком наград | `AchievementsScreen.tsx` |
| Нарисованный «индикатор Home» внизу экрана приветствия | `WelcomeScreen.tsx` |
| Неиспользуемые экраны: старая главная, `SharedSetDetailScreen`, `EmailAuthScreen`, `SecurityScreen`, `SubscriptionScreen`, `StudyPlaceholderScreen` | `src/screens/` |
| Правильный/неверный ответ — добавить иконку ✓/✕ к цвету (доступность) | экраны тренировок |
| Меньше игровых «валют» (серия, алмазы, опыт, награды, очки) | продукт |
