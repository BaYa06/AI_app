# План: главная — «Урок дня» и порядок экрана

Цель — чтобы главная отвечала на вопрос **«что мне делать сейчас?»** одной кнопкой. Наверху одна главная карточка «Урок дня», ниже мини-игры, ещё ниже наборы; редкие действия уходят в меню.

Наглядный разбор с макетами, состояниями и правилами: https://claude.ai/artifact/3qCrhHM2wy5bmXkkvWz6hv

## Почему

- Главное действие («Повторение дня») сейчас на 4-м месте: над ним карусель из трёх ярких мини-игр, тизер рейтинга, а в шапке залитый «+». Взгляд цепляется за них, а не за учёбу.
- **Новые слова не попадают в «Повторение дня».** `isCardWaitingReview` (`SRSService.ts`) берёт только карточки с `learningStep ≥ 1`. У человека с 10 новыми наборами по 30 слов в первый день кнопки нет, вместо неё «Учить все карточки» с выбором режима на все 300 слов. Больше всего выбора и никакого плана — ровно тогда, когда человек решает, остаться ли в приложении.

## Связь с планом брендбука

`brandbook_migration.md` запрещает менять состав и порядок главной. **Этот план — отдельное продуктовое решение**, которое снимает запрет для главной (шаг 0.1). Все остальные правила брендбука действуют: только токены, компоненты `ui`, иконки lucide, тексты на «ты», одна залитая кнопка на экран.

## Как работать с планом

- Шаги идут по порядку. Этап 1 (логика) — раньше этапа 2 (вид): карточка наверху бесполезна, пока ей нечего предложить новичку.
- Один шаг = один коммит. В сообщении — номер шага: `Home 1.2: …`.
- После каждого шага:
  - типы без новых ошибок. **`npx tsc --noEmit` в корне падает** (`RangeError: Maximum call stack size exceeded`: у `tsconfig.json` нет `include`, и `tsc` лезет в `dist/`, `ios/build`, `ios/Pods`…) — так было и до этого плана, и фильтр по `error TS` принимал падение за «0 ошибок». Проверять только `src/`: временный конфиг `{ "extends": "<repo>/tsconfig.json", "include": ["<repo>/src", "<repo>/*.d.ts"] }` → `npx tsc --noEmit -p <конфиг>`; старых ошибок **64** (неиспользуемые переменные и т. п., до плана было 67) — новых быть не должно;
  - `npm run brand:check` — нарушений не больше, чем до шага;
  - экран проверен в светлой и тёмной теме, на ширине iPhone SE (375 pt);
  - долгие локальные сборки iOS не запускаем — проверка через TestFlight.
- Новый код главной выносим в `src/components/home/` — `HomeScreen.new.tsx` (≈2 600 строк) не должен расти.
- Отмечать `[x]` по мере выполнения.

## Правила урока дня (источник правды для этапа 1)

| Правило | Значение |
|---|---|
| Порядок | сначала повторение, потом новые слова |
| Повторение | все слова с `isCardWaitingReview`, самые просроченные первыми (как сейчас) |
| Потолок урока | 30 карточек (`DAILY_REVIEW_MAX`) |
| Новых в день | настройка `dailyNewCardsLimit`: 5 / 10 / 20, по умолчанию 10 |
| Квота новых | `min(dailyNewCardsLimit, max(0, 30 − ждали повторения утром))` |
| Откуда новые | один «текущий» набор, по порядку добавления (`createdAt`); закончился — следующий |
| Текущий набор | выбранный вручную → иначе последний изученный (`lastStudiedAt`) с новыми словами → иначе первый в списке по текущей сортировке |
| Как учить новое | сначала карточки с самооценкой (`Study`, `mode: 'classic'`), потом проверка тестом |
| Как учить повторение | тест (`MultipleChoice`), как сейчас |
| Время | `round((повторить × 15 с + новых × 22 с) / 60)` минут, минимум 1 (`estimateMinutes`) |
| Какие наборы | текущий курс (`filteredSets`), как сейчас |
| Учитель | урока нет, остаётся баннер учителя |

**«Утренний снимок».** Квота новых считается один раз за день, по числу слов, ждавших повторения при первом открытии главной. Иначе после 30 повторений из 40 квота «вернётся», и человеку предложат ещё 10 новых, хотя мы обещали «новые — завтра».

**Правила SRS не меняем.** Уровень карточки по-прежнему считает сервер (`api/progress.js`), `applyAnswer` — его зеркало. Новая карточка (`step 0`) считается «пришедшей» (`isCardDue`), поэтому оценка «Почти» или «Уверенно» в карточках переводит её на шаг 1 со сроком через день, а «Не знаю» оставляет на шаге 0.
