# Контроль выхода из приложения во время теста

Проблема: во время живого теста (TestExamScreen) ученик сворачивает приложение, ищет ответ в
другом приложении и возвращается. Ещё хуже: если убить приложение и снова ввести код, сервер
пускает обратно на тот же вопрос (`join` → `alreadyJoined`, TestJoinScreen.tsx:116, план
App Review, пункт 40).

Шаг = коммит «Exam N». Порядок выкладки — по plan/release_safety.md: сначала сервер, потом
приложение.

## Что технически возможно

**Запретить выход на iOS нельзя.** Жест «домой», переключатель приложений, Пункт управления,
кнопка блокировки — система не даёт приложению их перехватить. Единственный настоящий замок —
Guided Access / Single App Mode, но он работает только на устройствах под MDM (школьные
iPad под управлением). Свой экран «Вы уверены?» на жест «домой» показать невозможно, и
закрывать приложение программно Apple не разрешает (отклонят на ревью).

На Android можно перехватить кнопку «Назад» (BackHandler) и закрепить экран (screen pinning),
но закрепление ученик подтверждает сам и может снять.

Поэтому концепция: **не «запретить», а «сделать выход бессмысленным»**. Ученик заранее знает
правило, выход из приложения сразу завершает его попытку, учитель видит это в реальном
времени. Подсмотреть ответ можно, вернуться и ввести его нельзя.

## Поведение для ученика

1. **Перед стартом** (TestWaitingScreen) — карточка с правилами: «Не сворачивайте приложение.
   Если выйти из приложения во время теста, он завершится, и результат уйдёт учителю».
   Тест не начинается, пока ученик не нажал «Понятно».
2. **Во время теста:**
   - Экран не гаснет (keep-awake), иначе автоблокировка на вопросе без таймера считалась бы
     выходом.
   - Сверху маленькая плашка «Контролируемый режим» — постоянное напоминание.
3. **Попытка выйти внутри приложения** (кнопка «Завершить тест» в шапке, «Назад» на Android) →
   экран-предупреждение:
   > **Завершить тест?**
   > Вы ответили на 7 из 20. Неотвеченные вопросы засчитаются как неверные.
   > Результат сразу отправится учителю, вернуться к тесту будет нельзя.
   > [Продолжить тест] (основная) · [Завершить] (деструктивная)

   «Завершить» → результат уходит учителю → экран итогов. Android дополнительно может закрыть
   приложение (`BackHandler.exitApp()`), на iOS остаёмся на экране итогов.
4. **Выход из приложения** (свернул, переключился, заблокировал телефон):
   - Короткие системные шторки (Пункт управления, уведомления, начатый и отменённый жест
     «домой») меняют состояние только на `inactive`, это **не** считается.
   - Переход в `background` = выход. Даётся **льгота 3 секунды**: если ученик сразу вернулся
     (случайный жест), тест продолжается, но учитель видит «вышел на 2 с».
   - Вернулся позже → вместо вопроса экран «Тест завершён: вы вышли из приложения. Результат
     отправлен учителю» и счёт по отвеченным вопросам.
5. **Убил приложение и ввёл код заново** → сервер не пускает назад на вопрос, а завершает
   попытку с причиной «перезапуск приложения».

## Поведение для учителя

1. **При создании теста** (ExamLobbyScreen) — переключатель «Контроль выхода из приложения»,
   по умолчанию включён. Без него всё работает как сейчас (для самостоятельной практики).
2. **Во время теста** (LiveTestScreen) у ученика новые состояния:
   - «Вышел из приложения · 7/20» (красный) — попытка завершена;
   - «Выходил на 2 с» (жёлтый значок) — вернулся в пределах льготы;
   - «Старая версия приложения» — контроль выхода у него не работает (см. Exam 1, п. 4).
3. **«Разрешить продолжить»** у вышедшего ученика. Обязательная кнопка: ложные срабатывания
   будут (входящий звонок, случайная блокировка, сбой приложения). Ученик видит на экране
   «Учитель разрешил продолжить» и продолжает с того же вопроса.
4. **В результатах** (TestResultsTeacherScreen и CSV): колонка «Выход из приложения» (нет /
   завершил сам / вышел из приложения / перезапуск) и число коротких выходов.

## Exam 1 — сервер ✅
Только добавляем (release_safety, Release 2).
1. ✅ Миграция 025 (api/_db-init.js, database/migrations/025_exam_exit_control.sql):
   - `test_sessions.exit_control BOOLEAN DEFAULT FALSE`. Старый клиент учителя его не шлёт,
     и его тесты ведут себя как раньше.
   - `test_participants`: `away_at TIMESTAMPTZ`, `away_count INT DEFAULT 0`,
     `left_reason VARCHAR(20)` (`manual` | `background` | `relaunch` | NULL),
     `client_exit_control BOOLEAN DEFAULT FALSE`, `rejoin_allowed BOOLEAN DEFAULT FALSE`
     (учитель разрешил продолжить → следующий `join` не «перезапуск»; сбрасывается в `answer`).
2. ✅ `create`: необязательный `exitControl` (по умолчанию false для старых клиентов; новое
   приложение учителя шлёт true, если переключатель включён).
3. ✅ Новые действия (старые не трогаем):
   - `away`: ученик ушёл в фон, записать `away_at = NOW()`, broadcast `student_away`.
   - `back`: ученик вернулся. Сервер сам считает `NOW() - away_at` (клиенту не верим):
     ≤ 3 с → `away_count += 1`, broadcast `student_back`, ответ `{ continue: true }`;
     > 3 с → завершить попытку (`finished_at`, `score` по формуле из `finishTest`,
     `left_reason = 'background'`), broadcast `progress_update` с `left: true`.
     Если `away` не дошёл (нет сети), `back` всё равно засчитывает выход, раз клиент сам
     сообщил, что был в фоне.
   - `leave`: кнопка «Завершить» → то же завершение с `left_reason = 'manual'`.
   - `reinstate` (только учитель-владелец, только при `left_reason`): сбросить `finished_at`,
     `score`, `left_reason`, `away_at`, поставить `rejoin_allowed`, broadcast `reinstated`
     с `userId` и `progress_update` с `done: false`.
4. ✅ `join`: новый клиент шлёт `exitControl: true` → `client_exit_control = true`. Если сессия
   с `exit_control` и **уже идёт**, а участник с незавершённой попыткой входит заново (и
   `rejoin_allowed = false`; если true — пустить и сбросить флаг), это
   перезапуск: завершить с `left_reason = 'relaunch'` и вернуть `{ leftReason }`.
   Если сессия с `exit_control`, а клиент старый (не прислал флаг), пускать, но учитель
   видит «Старая версия». Не отказываем: иначе ученик со старой версией из App Store не
   попадёт на тест совсем.
5. ✅ `get-question` и `answer`: если `left_reason IS NOT NULL` → 409 `{ left: true }`. Это и
   закрывает дыру: даже модифицированный клиент не сможет ответить после выхода.
   `answer` дополнительно сбрасывает `rejoin_allowed = false`.
6. ✅ `monitor` и `results`: новые поля `leftReason`, `awayCount`, `clientExitControl`
   (в `monitor` ещё `away` и `exitControl` сессии). В `monitor` поля участников — только
   учителю: ученикам незачем видеть, кто из одноклассников выходил.

## Exam 2 — ученик: отслеживание выхода ⬜
1. Хук `useExamExitGuard(participantId, enabled)` в src/hooks:
   - `AppState`: `active → background` → `away` (best effort, JS успевает отправить запрос
     до засыпания); `background → active` → `back` → по ответу продолжить или открыть экран
     «Тест завершён».
   - Флаг «был в фоне» в памяти + AsyncStorage, чтобы `back` отправился даже после
     переподключения сети.
   - Web (index.web.js): `document.visibilitychange` (hidden = background). `window.blur` не
     используем: слишком много ложных срабатываний.
2. iPad Split View / Slide Over и мультиоконность Android: приложение остаётся `active`,
   рядом открыто другое. Признак: ширина окна (`useWindowDimensions`) меньше ширины экрана →
   перекрывающий экран «Разверните приложение на весь экран, чтобы продолжить», вопрос
   скрыт, таймер идёт. Учителю отправляем `away` с причиной `split`.
3. Keep-awake на время TestExamScreen (`react-native-keep-awake` или нативный
   `isIdleTimerDisabled` через существующий модуль), снимается при уходе с экрана.
4. TestJoinScreen: обработать `leftReason` из `join` → экран «Тест завершён».
5. Ответ 409 `{ left: true }` в `get-question`/`answer` → тот же экран (подстраховка).

## Exam 3 — ученик: предупреждение и правила ⬜
1. Компонент `ExamExitDialog` на текущих UI-компонентах (brandbook): текст из раздела
   «Поведение для ученика», п. 3, с реальным числом отвеченных вопросов.
2. TestExamScreen: кнопка «Завершить» в шапке; `BackHandler` на Android и `beforeRemove`
   навигации → диалог вместо выхода. «Завершить» → `leave` → TestDone с пометкой «Результат
   отправлен учителю».
3. TestWaitingScreen: карточка правил + «Понятно» (только если `exit_control`; флаг
   приходит в ответе `join`).
4. Плашка «Контролируемый режим» в шапке TestExamScreen.
5. TestDone: вариант для `left_reason` («Вы вышли из приложения во время теста»), без
   разбора правильных ответов, чтобы итоги не превратились в шпаргалку для других.
6. Realtime `reinstated` → «Учитель разрешил продолжить» → вопрос `answer_count`.
7. **Ошибка, найденная в Exam 1:** TestExamScreen подписан на канал `test:${sessionId}:exam`, а
   сервер шлёт в `test:${sessionId}`. Поэтому ученик сейчас не получает даже
   `test_finished`, когда учитель завершает тест. Переподписать на `test:${sessionId}`
   (проверить, что TestWaitingScreen к этому моменту отписался), иначе `reinstated` тоже не
   дойдёт.

## Exam 5 — проверка ⬜
На staging-сборке (release_safety, Release 3), два устройства: учитель + ученик.
- свернул на 1 с и вернулся → продолжает, у учителя «выходил на 1 с»;
- свернул на 10 с → «Тест завершён», у учителя «Вышел · N/20»;
- Пункт управления / шторка уведомлений → ничего не происходит;
- убил приложение, ввёл код → «Тест завершён (перезапуск)»;
- учитель «Разрешить продолжить» → ученик продолжает с того же вопроса;
- кнопка «Завершить» → диалог → «Продолжить» возвращает, «Завершить» отправляет;
- iPad Split View → перекрывающий экран;
- старая версия из App Store + сервер с Exam 1 → тест проходится как раньше, у учителя
  метка «Старая версия»;
- тест с выключенным контролем → поведение как сейчас.

## Открытые решения
- **Льгота 3 секунды**: меньше — больше ложных срабатываний от случайных жестов; больше —
  успевают быстро подсмотреть. Можно вынести в настройки теста (0 / 3 / 10 с).
- **Блокировка телефона = выход.** Отличить блокировку от сворачивания без нативного кода
  нельзя. Keep-awake убирает автоблокировку; ручную блокировку учитель снимает кнопкой
  «Разрешить продолжить».
- **Устный тест** (OralTestSessionScreen) в этот план не входит: там учитель и так видит
  ученика вживую.
- **Школьные iPad под MDM** — позже можно добавить настоящий замок
  (`UIAccessibility.requestGuidedAccessSession`), он работает только на управляемых
  устройствах.
