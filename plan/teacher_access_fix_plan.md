Нумерация сквозная (1, 2, 3...) по всему файлу, независимо от блока — чтобы можно было сказать "почини 4, 12, 27" без уточнения блока.

**Как пользоваться:** ничего не чинится, пока вы не укажете номера. Когда назовёте номера — беру их в работу в указанном порядке.

В `NeonService.ts` на него переключены: `deleteCourse`, `renameCourse`, `createCourseInvite`, `getCourseInviteInfoByCode`, `getCourseInviteInfo`, `joinCourseByCode`, `joinCourseByToken`, `leaveStudentCourse`, `removeStudentFromCourse`, `loadCourseMembers`, `loadStudentCourseStats`, `toggleSetHiddenFromStudents`. - **Что НЕ сделано и почему:** `POSTGRES_URL` физически остаётся в бандле — его целиком убрать нельзя, пока не мигрированы остальные функции NeonService (карточки, повторения, стрик, библиотека и т.д.), это отдельная, гораздо более крупная работа (см. "Полная миграция" в исходном плане). `isCourseOwner`, `loadCourseSetStats`, `loadCourseActivityChart`, `loadSetHardCards`, `loadCourseSetsByMembership` пока не переведены (это ниже по severity — Weak/Medium, а не Critical/Broken). Ротацию `POSTGRES_URL`/ключа GCP в Neon/GCP-консоли должен сделать пользователь вручную — у меня нет туда доступа.
- **Побочная находка при реализации:** `API_BASE = __DEV__ ? 'http://localhost:3000/api' : '/api'` (используется в `TestJoinScreen.tsx`, `ExamLobbyScreen.tsx`, `LiveTestScreen.tsx`, `TestWaitingScreen.tsx`, `TestLobbyScreen.tsx`, `TestExamScreen.tsx`, `TestHistoryScreen.tsx`, `TestResultsTeacherScreen.tsx`, `src/utils/distractors.ts`, и похоже в `pushNotifications.ts`/`NeonService.ts` для `/api/push`) — относительный URL `'/api'` не резолвится в `fetch()` на нативном React Native (в отличие от веба/браузера), то есть **вся фича живых письменных тестов, скорее всего, не работает вообще в собранном iOS/Android-приложении**, только в `__DEV__`/на вебе. В новом `api/teacher.js`-клиенте использован абсолютный URL (`https://ai-app-seven-zeta.vercel.app/api/...`), проблема не повторена. Старые файлы не трогал — это отдельная, ранее не внесённая в план находка; добавил её отдельным пунктом 55 ниже.
- **Не проверено на реальном устройстве** — нет доступа к запущенному билду; логика проверена чтением кода и типами (`tsc` не показывает новых ошибок).
- **Проблема:** Строка подключения к продовой Neon Postgres инлайнится в JS-бандл через `babel-plugin-transform-inline-environment-variables`. Даёт полный read/write/DDL доступ к БД, извлекаемый из установленного .ipa/.apk. Обесценивает почти все проверки прав во всём приложении.
- **План починки:**
  1. Убрать `POSTGRES_URL` (и все его алиасы `EXPO_PUBLIC_POSTGRES_URL`/`REACT_APP_POSTGRES_URL`/`NEXT_PUBLIC_POSTGRES_URL`) из списка `include` в `babel.config.cjs`.
  2. Поднять тонкий backend-слой (аналог уже существующего `api/test.js`) для каждой мутации, которая сейчас идёт из `NeonService.ts` напрямую с клиента — как минимум для всех учительских операций (курсы, инвайты, ростер, видимость наборов).
  3. Backend должен проверять `Authorization: Bearer <supabase JWT>` через `supabase.auth.getUser(token)` на каждый запр&#8203;рос, а не доверять `userId`/`teacherId` из тела запроса.
  4. Ротировать текущий `POSTGRES_URL` в Neon (он уже был в опубликованных билдах — считать скомпрометированным).
  5. Постепенная миграция: можно переносить функции NeonService в backend по одной, начиная с самых критичных (см. пп. 8, 15, 18, 20 ниже), а не одним большим рефакторингом.

### 7. deleteCourse удаляет курс по id без проверки владельца
- **Файл:** `src/services/NeonService.ts:993-1000` (было 971-990)
- **Severity:** Critical · **Статус:** ✅ Сделано (2026-09-18, как часть пункта 1)
- **Проблема:** `DELETE FROM courses WHERE id = courseId`, без `AND user_id = ...`. Из-за `ON DELETE CASCADE` удаление чужого courseId дополнительно молча удаляло всех его учеников и все инвайты.

### 12. Гонка при первом создании инвайта — нет UNIQUE(course_id)
- **Файл:** `database/migrations/013_course_invites_unique.sql`, `api/teacher.js` (`createInvite`, `regenerateInvite`)
- **Severity:** Medium · **Статус:** ✅ Сделано (2026-09-22)
- **Проблема:** Двойной тап по "Пригласить" мог создать два разных token/join_code для одного курса.
- **Что сделано:**
  1. Миграция 013 добавила `UNIQUE (course_id)` на `course_invites` — применена к живой БД (дублей на момент проверки не было, дедупликация не потребовалась).
  2. `createInvite` переписан на один атомарный `INSERT ... ON CONFLICT (course_id) DO UPDATE ... RETURNING` вместо "сначала SELECT, потом решить, вставлять или нет" — при гонке двух одновременных запросов UNIQUE-констрейнт гарантирует одну строку, и оба запроса получат согласованный результат.
  3. Технический нюанс, который пришлось явно проверить: в Postgres `DO UPDATE ... WHERE <условие>` при ложном условии **не возвращает строку через RETURNING вообще** (не "просто не обновляет её"). Поэтому вместо `WHERE` использован `CASE` внутри `SET` — обновление формально происходит всегда, но переприсваивает старые же значения, если инвайт ещё не истёк. Проверено эмпирически на тестовой таблице перед применением к реальной логике.

### 55. API_BASE использует относительный URL '/api' — не работает на нативном приложении

- **Проблема:** `const API_BASE = __DEV__ ? 'http://localhost:3000/api' : '/api';` — в продакшен-сборке относительный путь не резолвится в `fetch()` на нативном React Native. Вся фича живых письменных тестов, скорее всего, полностью не работала в собранном iOS/Android-приложении.
- **Что сделано:**

  2. Все 9 файлов из исходного списка (8 экранов теста + `distractors.ts`) переведены на импорт из него вместо собственной копии константы.
  3. `NeonService.ts`: собственный `TEACHER_API_BASE` (уже был абсолютным — сделан вместе с пунктом 1) теперь тоже композируется из общего `API_BASE` (`` `${API_BASE}/teacher` ``) вместо дублирования домена; хардкоженный `fetch('/api/push?action=notify', ...)` (уведомление о потере streak) переведён на `` `${API_BASE}/push?action=notify` ``.

  5. `NotificationSettingsScreen.tsx`: два хардкоженных `/api/push` вызова переведены на общий `API_BASE`. Попутно нашёл и исправил соседний баг в том же вызове: `` `/api/push?action=settings?userId=${uid}` `` — второй `?` вместо `&`, из-за чего `req.query.userId` на сервере (`api/push.js`) всегда был `undefined` и загрузка сохранённых настроек уведомлений всегда падала с 400 (это чинилось попутно, не было отдельным пунктом плана, но напрямую в том же вызове).
  6. **Отдельная находка, шире исходного списка пункта 55:** `src/services/ApiService.ts` — тот же паттерн (`API_BASE_URL = __DEV__ ? ... : '/api'`), и он реально используется (`extractImageCards` — распознавание карточек по фото, вызывается из `SetDetailScreen.tsx`). Сделал абсолютным (`https://ai-app-seven-zeta.vercel.app/ai`), сохранив путь `/ai` — тот же баг с относительным URL на нативном RN, но не стал менять, какой бэкенд обслуживает эти вызовы, раз это явно осознанная инфраструктура, а не опечатка.
