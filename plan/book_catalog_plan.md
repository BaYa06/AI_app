# План: Каталог книг + импорт из Excel

Дата: 2026-09-24

## Идея

Ученики сами не создают карточки и учат по бумажным учебникам, а учитель не успевает наполнять приложение.
Решение — каталог готовых наборов под конкретные учебники:

**Книга → Юнит (глава) → Набор (карточки).** На старте 1 юнит = 1 набор, но схема допускает несколько наборов в юните.

- Мы (админ) загружаем книги из Excel скриптом.
- Учитель подключает книгу к своим курсам и открывает юниты в своём темпе. У каждой группы свой план: в 7А открыты Unit 1–3, в 7Б только Unit 1.
- Ученик в курсе видит только открытые юниты. Без курса он может сам открыть любую опубликованную книгу.
- **Дедлайнов нет** — только «открыт / закрыт».

## Архитектура (важно — не Supabase-данные)

- **Данные** — Neon Postgres. Миграции: `database/migrations/NNN_*.sql`, последняя — `016`.
- **Supabase** — только авторизация (JWT). RLS не используется и не нужен.
- **Проверка прав** — в Vercel-функциях `api/*.js`: JWT проверяется через `supabase.auth.getUser(token)`, `userId` из тела запроса не принимается. Образец — `api/teacher.js`.
- Всё новое по книгам идёт **только через `api/books.js`**, а не через прямые SQL-запросы из `NeonService.ts`.

Реальные таблицы:

| Сущность | Таблица | Ключевые поля |
|---|---|---|
| Пользователи | `users` | `teacher boolean` (роли admin нет) |
| Наборы | `card_sets` | `user_id`, `course_id` (один курс), `is_hidden_from_students`, `language_from/to` |
| Карточки | `cards` | `front`, `back`, `example` (нет `sort_order`) |
| Прогресс SRS | `card_progress` | PK `(user_id, card_id)` — привязан к `card_id` |
| Курсы | `courses`, `course_members` | |
| Библиотека | `library_sets`, `library_cards` | импорт **копирует** карточки в личный набор |

Следствия:
- Прогресс привязан к `card_id`, значит при обновлении карточки с сохранением id прогресс остаётся.
- Удаление карточки каскадно удаляет `card_progress` и `reviews`.
- Официальный набор нельзя положить в несколько курсов через `course_id`, поэтому связь идёт через `course_units`.
- Официальные наборы ученики учат **напрямую**, без копирования, иначе исправления в книге до них не дойдут.

## Часть 1. Миграция БД — `017_book_catalog.sql`

Старые миграции не редактируем. Всё через `IF NOT EXISTS`, чтобы миграция применялась и на чистой, и на текущей базе.

### Новые таблицы

**`books`**
- `id uuid PK default gen_random_uuid()`
- `title text not null`, `edition text`, `level text`, `subject text`
- `language_from varchar(10) not null` — язык изучения (`en`)
- `language_to varchar(10) not null` — язык перевода (`ru` / `ky`)
- `publisher text null`
- `is_published boolean not null default false`
- `created_at`, `updated_at timestamptz default now()`
- `UNIQUE (title, edition)`

**`book_units`**
- `id uuid PK`
- `book_id uuid FK → books ON DELETE CASCADE`
- `number int not null`, `title text not null`, `pages text null`, `sort_order int`
- `UNIQUE (book_id, number)`

**`course_books`**
- `course_id FK → courses ON DELETE CASCADE`, `book_id FK → books ON DELETE CASCADE`
- `created_at`, `PK (course_id, book_id)`

**`course_units`** — план юнитов для группы, **без дедлайна**
- `course_id FK → courses ON DELETE CASCADE`, `unit_id FK → book_units ON DELETE CASCADE`
- `is_open boolean not null default false`, `opened_at timestamptz null`
- `PK (course_id, unit_id)`

### Изменения существующих таблиц
- `card_sets`: `unit_id uuid NULL FK → book_units ON DELETE SET NULL`, `is_official boolean not null default false`.
- `cards`: `sort_order int NULL`.
- `users`: `is_admin boolean not null default false` (отдельный флаг рядом с `teacher`, без перехода на `role`).

### Индексы
- На все FK: `book_units(book_id)`, `course_books(book_id)`, `course_units(unit_id)`, `card_sets(unit_id)`.
- `card_progress(card_id)` — для статистики по юнитам (сейчас PK начинается с `user_id`).

### Уникальность карточек
Частичный уникальный индекс «только для официальных наборов» в Postgres не сделать: он не может смотреть в `card_sets`. Поэтому сопоставление карточек по `lower(trim(front))` делаем **в скрипте внутри транзакции** — для одного админа этого достаточно.

### 2.3. Формат Excel — один файл = одна книга

**Лист `Книга`** (одна строка данных):
`title | edition | level | subject | language_from | language_to | publisher`

**Лист `Карточки`**:
`unit | unit_title | pages | term | translation | example`

- `term` → `cards.front`, `translation` → `cards.back`.
- `unit`, `unit_title`, `pages` повторяются в каждой строке юнита.
- Порядок строк = `sort_order`.
- Несколько значений перевода — в одной ячейке через запятую.

### 2.4. `scripts/import-book.ts <file.xlsx> [--dry-run] [--publish] [--prune]`

**Валидация (до записи):**
- Оба листа есть, обязательные колонки на месте (без учёта регистра и пробелов).
- Trim всех значений, пустые строки пропускаются.
- Ошибка: разные `unit_title`/`pages` у одного номера юнита; пустой `term`/`translation`; `unit` не число.
- Предупреждение: дубль `term` внутри юнита (оставляем первый).
- Все ошибки выводятся списком с номерами строк Excel. При любой ошибке ничего не пишется.

**Запись — одна транзакция `BEGIN … COMMIT`:**
1. Upsert книги по `(title, edition)`. Новая книга создаётся с `is_published = false`.
2. Upsert юнитов по `(book_id, number)`.
3. Для каждого юнита найти или создать `card_sets` с `unit_id`, `is_official = true`, `user_id = ADMIN_USER_ID`, названием `Unit {n} — {title}`, языками из книги.
4. Карточки: совпадение по `lower(trim(front))` → UPDATE `back`, `example`, `sort_order` **с сохранением id**. Новые → INSERT. Старые SRS-колонки в `cards` не трогать.
5. Карточки, которых нет в Excel: по умолчанию только вывести список. С `--prune` показать, у скольких учеников есть прогресс, спросить подтверждение `y/N` и только потом удалить.
6. Обновить `card_sets.total_cards`.

**Отчёт:**
```
Книга: Solutions Pre-Intermediate (3rd) — обновлена, статус: черновик
Юниты: 10 (2 новых, 8 без изменений)
Карточки: +34 новых, ~12 обновлено, 3 отсутствуют в Excel (не удалены)
```

**Известное ограничение:** исправление опечатки в `term` создаёт новую карточку, прогресс по старой не переходит. Отчёт dry-run должен явно показывать пары «удалено X / добавлено Y» в одном юните, чтобы это было заметно.

## Часть 9. Выбор курса при скачивании набора из библиотеки

Касается **обычных наборов** из библиотеки (`library_sets`), не книг. Не зависит от частей 1–8, поэтому её можно сделать в любой момент, в том числе первой.

**Сейчас:** кнопка скачивания в `LibrarySetDetailScreen.tsx` копирует набор в личные наборы с `course_id = NULL`, и потом его нужно вручную переносить в курс.

**Как будет:** любой пользователь (ученик, учитель, гость) нажимает «Скачать» и выбирает курс. **Выбрать можно только один курс** — в отличие от книги, где выбор множественный.

```
Добавить «Irregular Verbs» в курс

  ◉ Без курса
  ○ 7А класс
  ○ Немецкий A1

        [ Добавить ]
```

Поведение:
- В списке только **свои** курсы (`courses.user_id = я`). Курсы, где пользователь ученик, не показываются: в чужой курс добавить набор нельзя.

- Если своих курсов нет, окно не показывается, и набор скачивается сразу, как сейчас.
- После добавления — тост «Добавлено в „7А класс"», набор появляется в этом курсе.
- Если выбранный курс учительский и в нём есть ученики, под курсом подсказка: «Набор сразу увидят ученики курса» (`is_hidden_from_students = false` по умолчанию).

## Итоговые критерии приёмки

1. Миграция применяется на чистой и на текущей базе, существующие данные не затронуты.
2. Шаблон создаётся, dry-run даёт понятный отчёт.
3. Файл с ошибками → список ошибок с номерами строк, ничего не записано.
4. Первый импорт создаёт черновик: его видит admin и не видит обычный пользователь.
5. Повторный импорт: 0 новых, 0 дублей; изменённый перевод сохраняет id и прогресс.
6. `--publish` делает книгу видимой всем авторизованным.
7. Учитель подключает одну книгу к двум курсам, открывает разные юниты, и ученики каждой группы видят только свои.
8. Обычный пользователь не может изменить официальный набор через API (полная гарантия — после части 0.4–0.5).

## Порядок работы

Часть 0 (минимум) → 1 → 2 → **вы тестируете импорт** → 3 → 4 → 5 → 6 → 7. Часть 8 идёт параллельно.
Часть 9 независимая — её можно сделать в любой момент.
После каждой части — короткий итог: что сделано, какие файлы изменены, что проверить вручную.
