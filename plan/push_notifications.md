# План: push-уведомления как триггер возврата

Цель — чтобы push был **поводом открыть приложение и сразу сделать урок**, а не шумом, который отключают. Каждое уведомление ведёт в конкретное действие (урок дня, слова, рейтинг), и по каждому мы знаем, дошло ли оно до завершённого урока.

Главная метрика плана — **push → урок завершён**: доля отправленных пушей, после которых человек в течение 6 часов закончил урок. Открытия, opt-in и прочее — промежуточные цифры.

## Почему

- Push — единственный канал, который возвращает человека без его инициативы. В приложении для повторения слов от него зависит, будет ли привычка.
- Инфраструктура уже есть (FCM, cron, 11 типов сообщений), но **мы не знаем, работает ли она**: нет журнала отправок, тап по пушу никуда не ведёт и не логируется, `pushNotificationOpened` объявлен в `analytics.ts`, но нигде не вызывается.
- Разрешение на iOS спрашивается **сразу после онбординга системным диалогом**. Диалог показывается один раз в жизни приложения, и его тратят на человека, который ещё не понял, зачем ему напоминания.
- В API есть дыры безопасности: часть ручек принимает `userId` из запроса без проверки входа (подробно в этапе 0).

## Как работать с планом

- Шаги идут по порядку. **Этап 0 (безопасность и замеры) обязателен до любых новых уведомлений**: без журнала отправок мы не сможем сравнить «до» и «после».
- Один шаг = один коммит. В сообщении — номер шага: `Push 1.2: …`.
- После каждого шага:
  - типы без новых ошибок: проверять только `src/` (временный конфиг с `include: ["src", "*.d.ts"]`), старых ошибок 64, новых быть не должно;
  - `npm run brand:check` — нарушений не больше, чем до шага (тексты пушей тоже на «ты» по брендбуку);
  - серверные изменения проверены вызовом ручки с `dry_run=1` (появляется в шаге 0.4);
  - долгие локальные сборки iOS не запускаем, проверяем через TestFlight.
- Новые серверные модули пушей кладём в `api/push/` (там уже лежит `_push-store.js`, его удаляем в 0.3). Номера миграций: 024–025 заняты, пушам — 026 `push_log`, 027 `notif_days_custom`, 028 `push_tokens.permission`, 029 `user_habits`, 030 «о себе» (`age_range`, `class_days`, `class_hour`, `notif_use_habits`), 031 `courses.schedule`, 032 `card_sets.announced_at`, 033 `push_views`. `api/push.js` не должен расти: в нём остаётся только маршрутизация.
- Отмечать `[x]` по мере выполнения.

## Принципы (источник правды для текстов и правил)

1. **Одно маркетинговое уведомление в день.** Исключения: уведомления от учителя (транзакционные) и «серия сгорит» вечером, если серия ≥ 3 дней. Абсолютный потолок — 2 пуша в сутки.
2. **Тихие часы — с 22:00 до 8:00 по часовому поясу пользователя.** Ничего не отправляем, даже транзакционное: оно уходит в 8:00.
3. **Конкретика вместо призывов.** Не «Пора учиться!», а «12 слов ждут · ~3 мин». В каждом пуше есть число или имя, иначе он не отправляется.
4. **Тап ведёт в действие, а не на главную.** «Слова ждут» открывает сразу урок, «рейтинг» открывает рейтинг курса.
5. **Без давления на вину и без фальшивой срочности.** Никаких «Ты нас бросил 😢». Серия и рейтинг — настоящие механики, о них говорим честно.
6. **Игнор — это сигнал.** 3 пуша подряд без открытия → шлём через день; 7 подряд → раз в неделю; открыл → обычный режим (шаг 2.3).
7. **Не показываем на экране блокировки чужие данные.** Имя другого ученика в «тебя обогнал…» — только имя без фамилии и только внутри курса, где рейтинг включён.
8. **Всё, что отправляется, пишется в `push_log`**, включая пропуски (тихие часы, лимит, отложено, контрольная группа). Без этого не найти, где люди отпадают.

**Лестница возврата** (заменяет `reactivation_3d` / `reactivation_7d`):

| День | Посыл | Пример |
|---|---|---|
| 2 | слова ждут | «18 слов ждут повторения · ~5 мин» |
| 4 | слова забываются | «Без повторения 9 слов скоро забудутся» |
| 7 | прогресс | «Ты выучил 140 слов. Не дай им пропасть» |
| 14 | новое / лёгкий вход | «Начни с 5 слов — займёт минуту» |

## Воронки: где люди отпадают

Четыре воронки. Под каждым шагом указано, откуда берутся данные.

**1. Активация (новичок)**
`app_open (first_open)` → `sign_up` → `onboarding_complete` → `set_created / set_imported` → `lesson_started` → `lesson_completed` → **вернулся на 2-й день** (D1) → D7 → D30
Источник: GA4. Самый большой отвал ожидаем между `onboarding_complete` и первым `lesson_started`: на этот разрыв и нацелен `onboarding_first_lesson`.

**2. Разрешение на уведомления**
`push_preprompt_shown` → `push_preprompt_accepted` / `push_preprompt_later` → `push_permission_granted` / `push_permission_denied` → (позже) `push_permission_revoked`
Источник: GA4 + колонка `permission` в `push_tokens`.

**3. Пуш → урок (главная)**
`eligible` (кандидат в этот час) → `sent` → `delivered` (успех FCM) → `opened` → `lesson_started` → `lesson_completed` → **вернулся на следующий день сам, без пуша**
Источник: `push_log` (с `eligible` по `opened`), GA4 + серверная отметка урока (`lesson_*`). Последний шаг показывает, формирует ли пуш привычку или только костыль.

**4. Отток канала**
`push_disabled_in_app` (выключил в настройках, по категориям) / `push_permission_revoked` (выключил в iOS) / `token_unregistered` (удалил приложение)
Источник: `push_log`, `push_tokens`, настройки. **Это главный предохранитель:** если какой-то тип пушей даёт рост отключений, его выключаем, даже если он хорошо открывается.

**Контрольная группа (holdout).** 10 % пользователей не получают маркетинговых пушей вообще (учитель и транзакционные — получают). Только так можно честно посчитать, сколько retention даёт сам push. Без неё рост может быть сезонным или эффектом других изменений, например новой главной. Это ответ на вопрос «выгодно ли»: сравниваем D7 и D30 у группы с пушами и у контрольной.

**Ориентиры** (сверить с нашими данными после этапа 0; это типичные цифры для образовательных приложений, не обязательство):

| Метрика | Ориентир | Красный флаг |
|---|---|---|
| Opt-in на iOS | ≥ 60 % (после этапа 1) | < 40 % |
| Открытие пуша | 6–12 % | < 3 % |
| Открыл → урок завершён | ≥ 40 % | < 20 % (тап ведёт не туда или урок слишком длинный) |
| Отключили в неделю | < 1 % получателей | > 2 % |
| D7: пуши против контрольной | +3–8 п. п. | ≤ 0 (пуши не работают или раздражают) |

## Этап 2б. Профиль привычек пользователя

Чтобы пуш приходил вовремя и о нужном, сервер должен знать, **когда, как и в каком контексте человек учится**. Строим профиль из трёх честных источников.

**Чего не делаем и почему.** Данные из других приложений iOS не отдаёт. Окно App Tracking Transparency разрешает только рекламный идентификатор (IDFA) для рекламных сетей, а не чтение чужих данных. Screen Time API требует отдельного разрешения Apple для родительского контроля, и данные не покидают устройство. Доступ к календарю пугает людей и вызывает вопросы на ревью. Возраст Apple не отдаёт. Среди учеников курсов есть школьники, поэтому профиль на сторонних данных — это риск отказа в App Store (п. 5.1) и нарушения закона о персональных данных. **Только своё поведение в приложении + то, что человек сказал сам + то, что указал учитель.**

| Поле профиля | Источник | Как считаем | Зачем пушам |
|---|---|---|---|
| Привычный час | поведение | мода часа начала уроков за 14 дней в поясе пользователя | время отправки (3.6) |
| Привычные дни | поведение | дни недели с уроками за 4 недели (≥ 2 раз) | не шлём в дни, когда он обычно не учится, если не просил |
| Тип дня | поведение | `weekday` / `weekend` / `both` | разное время в будни и выходные |
| Длина урока | поведение | медиана `lesson_completed.duration` | «~3 мин» в тексте подстраиваем под реальность |
| Любимый режим | поведение | частота `study_mode` | тап открывает его, а не общий урок |
| Точность | поведение | доля верных за 14 дней | при низкой — мягкие тексты, меньше новых слов |
| Сам или на курсе | поведение | есть ли `course_members.role = 'student'` | категория «Курс» и тексты от учителя |
| Сегмент активности | поведение | `new` (< 7 дн.) / `daily` (≥ 5 дн. из 7) / `regular` (2–4) / `casual` (1) / `sleeping` (0 за 7 дн.) / `lost` (> 30) | выбор сценария и частоты |
| Цель | вопрос | уже есть `users.learning_goal` | тексты («к экзамену», «для поездки») |
| Возраст | вопрос | диапазон: до 13 / 13–17 / 18–24 / 25–34 / 35+, можно пропустить | до 18 — без рейтинга чужих имён и без вечерних пушей после 21:00 |
| Занятия в центре | вопрос + учитель | «Хожу на курсы: пн, ср, пт в 18:00» или расписание курса | пуш «повтори перед занятием» за 1–2 ч до урока в центре |

## Безопасность и приватность (чек-лист на каждый шаг)

- Любая ручка, которая читает или меняет данные пользователя, берёт `userId` **только из JWT** (`getAuthedUserId`), не из тела или query.
- Серверные ручки (`notify`, `cron-*`) закрыты секретом; секреты сравниваются за постоянное время и живут только в переменных Vercel. `FIREBASE_SERVICE_ACCOUNT.json` и другие ключи в корне — в `.gitignore` и в историю git не попадали (проверено 06.10.2026). Новые ключи добавлять так же.
- В тексте пуша нет email, фамилий, оценок учителя и чужих данных вне курса. На экране блокировки его видят другие люди.
- Уникальный индекс в `push_log` и почасовой cron защищают от двойной отправки. `PUSH_PAUSED` выключает рассылку без деплоя.
- Пользователь управляет всем из приложения: категории, время, дни. «Выключить всё» в приложении работает, даже если в iOS разрешение остаётся.
- App Store (п. 4.5.4): рекламные и промо-пуши только с отдельным явным согласием. В этом плане их нет. Если появятся (скидка на премиум) — отдельная категория, выключенная по умолчанию.
- Обновить политику конфиденциальности: какие уведомления, на основе каких данных, журнал хранится 180 дней.

## Ручная проверка (перед каждым выпуском в TestFlight)

- Новый аккаунт: после онбординга системного диалога нет; после первого урока появляется лист с выбором времени.
- Тап по пушу из закрытого приложения и из фона открывает нужный экран; в `push_log` появляется `opened_at`.
- Тихие часы: `dry_run` в 23:00 по поясу тестового аккаунта даёт `quiet_hours`.
- За сутки на один аккаунт приходит не больше 2 пушей.
- Выключенная категория не приходит.

## Не входит в план

- Android-пуши. Нужен `google-services.json`, каналы уведомлений и разрешение `POST_NOTIFICATIONS` (Android 13+). Отдельный план, когда Android-сборка пойдёт в магазин.
- Email и Telegram как запасные каналы. Вернуться после 6.1, если opt-in останется ниже 50 %.
- Live Activity и виджет «серия». Сильный триггер, но отдельная нативная работа на Swift.
- Кнопки в уведомлении («Начать урок», «Напомнить через час»). Можно добавить после этапа 4 через категории APNs.
- Промо и монетизационные пуши (премиум, скидки).
