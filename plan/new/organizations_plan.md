# План: организации (учебные центры) и приватные книги

Цель — чтобы учебный центр мог пользоваться своими книгами в Flashly так, чтобы **их видели только его учителя и ученики**, а дальше — управлял своими учителями и группами сам и платил за доступ как организация.

## Почему

- Некоторые учебные центры не хотят, чтобы их книги были видны всем, — хотят дать доступ только своим учителям.
- Сейчас у книги два состояния: `books.is_published = true` (видят все) или черновик (видит только админ, `users.is_admin`). Понятия «книга центра» нет.
- **Дыра:** `fork-set` (`api/books.js`) копирует официальный набор в обычный набор учителя, и копию можно опубликовать в общую библиотеку (`api/library.js`, publish). Копия не помнит, из какой книги она сделана, поэтому запретить это сейчас нечем.

## Главное решение: организация — контейнер, а не третья роль

Не делаем «орг» ещё одной ролью пользователя рядом со «студент / учитель». Учитель может работать в двух центрах, директор центра может сам вести группу, ученик центра продолжает учить личные наборы.

```
Пользователь (один аккаунт: личные наборы, учёба)
  ├── членство в «Центр X»: роль = owner | admin | teacher | student
  └── членство в «Центр Y»: роль = teacher
```

Роль выдаётся **внутри организации**. Роль в курсе (`course_members.role`) остаётся как есть.

## Как работать с планом

- Этапы идут по порядку. Каждый этап полезен сам по себе, следующий можно отложить.
- Один шаг = один коммит. В сообщении — номер шага: `Org 1.2: …`.
- Миграции — через `psql "$DATABASE_URL_UNPOOLED" -v ON_ERROR_STOP=1 -f …`, одной транзакцией, идемпотентно (как `017_book_catalog.sql`). `database/apply-migration.js` для многострочных миграций не использовать.
- **Этапы 1–3 — только сервер и скрипты.** Приложение получает каталог книг с сервера, поэтому обновлять его в App Store не нужно. Новая сборка нужна только для видимых изменений в интерфейсе (значок «книга центра» и т. п.).
- Проверка типов — только `src/` (см. память: `tsc` в корне падает).
- Отмечать `[x]` по мере выполнения.

## Этап 1. Приватные книги центра (MVP, без интерфейса)

Сразу закладываем таблицы организаций, чтобы потом не переносить данные из «списков учителей». Управление — скриптами, руками админа Flashly.

### 1.1 Миграция `0XX_organizations.sql`
- [ ] `organizations (id, name, created_at)`
- [ ] `organization_members (organization_id, user_id, role, created_at)`, PK `(organization_id, user_id)`; `role IN ('owner','admin','teacher','student')`
- [ ] `books.organization_id UUID NULL REFERENCES organizations(id)` — `NULL` = общая книга, иначе приватная книга центра
- [ ] `card_sets.forked_from_set_id UUID NULL` — откуда скопирован набор (для запрета публикации)
- [ ] индексы: `organization_members(user_id)`, `books(organization_id)`

### 1.2 Правило доступа к книге (одно место в `api/books.js`)
Книгу видит пользователь, если:
- он админ Flashly, **или**
- книга общая (`organization_id IS NULL`) и опубликована, **или**
- книга приватная, опубликована, и пользователь — `owner | admin | teacher` этой организации, **или**
- пользователь — участник курса, к которому книга подключена (ученики видят только открытые юниты, как сейчас).

- [ ] вынести проверку в одну функцию и применить во всех местах, где сейчас `b.is_published = true OR admin`: `list-books`, `book-detail`, `course-plan`, `official-sets`, `fork-set` и выборка около `api/books.js:439`
- [ ] `attach-to-courses`: приватную книгу можно подключить только к курсу учителя этой организации
- [ ] без доступа — `404`, а не `403`, чтобы не раскрывать, что книга существует

### 1.3 Закрыть утечку через копии
- [ ] `fork-set` записывает `forked_from_set_id`
- [ ] публикация в библиотеку (`api/library.js`) отклоняет набор, если он скопирован из приватной книги
- [ ] решить: запрещать ли для приватных книг само копирование (строже) или только публикацию (мягче). По умолчанию — только публикацию.

### 1.4 Скрипты
- [ ] `scripts/org.ts create "Центр X"` — создать организацию
- [ ] `scripts/org.ts add "Центр X" teacher@mail.com --role teacher` / `--remove` / `list`
- [ ] `scripts/import-book.ts file.xlsx --org "Центр X"` — импорт сразу как приватной книги центра
- [ ] `scripts/publish-book.ts` — без изменений, публикация приватной книги делает её видимой только организации

### 1.5 Проверка
- [ ] учитель центра видит книгу в каталоге и подключает её к курсу
- [ ] его ученик видит открытые юниты через курс
- [ ] учитель другого центра и обычный пользователь не видят книгу ни в каталоге, ни в поиске, ни по прямому `bookId`
- [ ] копию набора из приватной книги нельзя опубликовать в библиотеку

## Этап 2. Организация в продукте

- [ ] **Приглашение учителей по коду или ссылке** (по аналогии с `course_invites`): владелец центра раздаёт ссылку, учитель сам вступает. Админу Flashly больше не нужно добавлять людей руками.
- [ ] курсы привязываются к организации: `courses.organization_id NULL`. Курс учителя центра по умолчанию принадлежит центру.
- [ ] при уходе учителя из центра его курсы центра остаются у центра (передаются другому учителю), а не исчезают
- [ ] в приложении: значок «книга вашего центра» в каталоге (нужна новая сборка)

## Этап 3. Веб-панель центра (в Flashly Admin, не в мобильном приложении)

Почему в вебе: обновления без проверки Apple, директору удобнее таблицы и статистика на компьютере, нет вопросов к оплате в App Store.

- [ ] вход для `owner | admin` организации (отдельно от супер-админа Flashly)
- [ ] учителя: список, приглашение, удаление, смена роли
- [ ] группы (курсы) центра: кто ведёт, сколько учеников, активность
- [ ] книги центра: загрузка Excel из панели вместо скрипта, публикация, снятие с публикации
- [ ] статистика: активные ученики, кто отстаёт, прогресс по юнитам
- [ ] брендинг: логотип и название центра у учеников (нужна новая сборка)

## Этап 4. B2B-оплата

- [ ] тарифы для центров: по числу учителей или учеников
- [ ] оплата по счёту или через сайт, **вне App Store** — допустимо по App Review Guidelines 3.1.3(c) (Enterprise Services: продажа организациям). Комиссия Apple не берётся.
- [ ] ученикам и учителям оплаченного центра открываются платные функции бесплатно
- [ ] в самом приложении не показывать цены и ссылки на оплату центра — иначе Apple может отклонить

## Открытые вопросы

- Может ли учитель одновременно состоять в нескольких центрах и видеть книги всех? (Предлагаемый ответ — да.)
- Видит ли владелец центра личные наборы своих учителей? (Предлагаемый ответ — нет, только наборы и статистику курсов центра.)
- Что происходит с курсами и прогрессом учеников, если центр перестал платить: доступ к приватным книгам закрывается, прогресс сохраняется.
- Нужна ли модерация общей библиотеки до этапа 4 (см. требования App Store 1.2 и возрастной рейтинг 13+ → 4+).
