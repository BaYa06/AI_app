# Кабинет учителя: главная, курс, задания (Teacher N)

Учителя заходят в приложение один раз: раздают доступ ученикам и больше ничего не делают. Ничего
не зовёт их обратно, а статистику приходится разбирать самому. Цель — чтобы у учителя каждый день
был повод открыть Flashly и понятное действие: урок, задание, кто отстаёт.

Макет (реальные данные Ильяз агая, A1-B и A1-E, на 12.11.2026):
https://claude.ai/artifact/5dmhuEVHCHqSbmnBGPwo33

Шаг = коммит «Teacher N». Отмечать ✅ по мере выполнения. Коммиты — в dev, база — только staging.

## Как читать план

- **Есть логика** — подключаем сразу к настоящим данным и серверу.
- **Логики нет** (задания, подготовка к уроку, пуши учителю) — делаем **только вёрстку** этих блоков
  и прячем их за флагом. Флаг в проде `false`: пользователи их не видят. Выдуманные цифры
  в рабочую сборку не попадают. Когда появится сервер (этапы 2–4), меняем данные блока
  и включаем флаг.
- Флаги в [features.ts](src/config/features.ts):
  - `TEACHER_CABINET_ENABLED` — новая главная и курс учителя (этап 1). `false` — всё как сейчас,
    откат одной строкой.
  - `TEACHER_HOMEWORK_ENABLED` — блоки заданий (этап 2). До этапа 2 — `false`.
  - `TEACHER_LESSON_PREP_ENABLED` — «Подготовка к уроку» (этап 3). До этапа 3 — `false`.

## Общие правила для всех шагов

### Светлая и тёмная тема

Макет нарисован только в светлой теме. Тёмную получаем из токенов, а не рисуем отдельно.

1. **Цвета только из токенов** `useThemeColors()` ([colors.ts](src/constants/colors.ts)),
   плашки — `alpha()` со ступенями 10 / 20 / 40 % (plan/done/brandbook.md). Никаких `'#…'` в экранах.
2. **Заливка под белый текст — `primaryFill`, не `primary`.** Карточка урока на главной, плитка
   «Живой тест», главные кнопки. В тёмной теме `primary` (#818CF8) под белым текстом нечитаем.
3. **Текст смысловых цветов — `*Text`-токены** (`successText`, `warningText`, `errorText`):
   «сдали», «не заходят 7+ дней», «до: …». Заливки `success` / `warning` / `error` — только
   для полосок, точек и фонов.
4. **Полоска «прошли / начали / не открывали»:** `success` / `warning` / трек `surfaceMuted`.
   В тёмной теме проверить, что сегменты различимы на `surface`.
5. **Новый токен `homework`** (этап 2, янтарный, на основе `warning` / `warningText`) — сразу
   в обеих темах.
6. **Проверка каждого шага** — скриншоты в светлой и тёмной теме: главная, курс, все окна.

### Модальные окна на iOS — нативные, на Swift

Образец — шторка режимов обучения: [StudyModeSheet.swift](ios/FlashcardsApp/StudyModeSheet.swift),
мост [StudyModeSheet.m](ios/FlashcardsApp/StudyModeSheet.m), JS-обёртка
[nativeStudyModeSheet.ts](src/components/study/nativeStudyModeSheet.ts). Каждое окно делаем так же:

1. **Swift-модуль** `RCTEventEmitter` + `.m`-мост. Лист показывает система
   (`UISheetPresentationController`, высоты `.medium()` / `.large()`, «ручка»), содержимое — SwiftUI
   в `UIHostingController`.
2. **Тема из JS:** нужные токены `useThemeColors()` передаются через `processColor` (свой список
   `COLOR_KEYS` на окно), плюс `dark` → `overrideUserInterfaceStyle`. Своих цветов в Swift нет.
   Тексты тоже приходят из JS, в Swift строк нет: одно место для правок и будущих переводов.
3. **Логика остаётся в JS.** Swift только показывает и присылает события (`create`, `copy`, `share`,
   `dismiss`…). Запросы к серверу, тосты и навигация — в JS-обёртке.
4. **Android, веб и сборки без нативного модуля** — RN-окно с той же раскладкой
   (`isNative…` = false). RN-версию делаем в том же шаге или до Swift.
5. **Нативный код не приходит обновлением по воздуху** — только новой сборкой. Нативные шаги
   выкладываются вместе с JS, который их вызывает (как Session 11 + 12).
6. Учесть план обновления RN (plan/new/rn_upgrade.md): мост пишем так же, как у уже работающих
   модулей, чтобы при переходе на новую архитектуру все окна переводились одинаково.

**Окна этапа 1:** «Новый курс», «Код подключения», «Выбери тип теста»
(сейчас RN-шторка [TestLobbySheet.tsx](src/screens/teacherCourseStats/TestLobbySheet.tsx)),
«Расписание» (сейчас RN [CourseScheduleSheet.tsx](src/components/push/CourseScheduleSheet.tsx)).
Шторка курсов — не модальное окно и остаётся как есть.

## Этап 2. Задания (сервер + интерфейс)

Экраны макета: 1а/1б, 4 (плитка), 11, 11а, 12, 12а, У0–У4. Новые окна («Новое задание»,
«Выбор слов», «Кто не сдал») — на Swift для iOS по общим правилам. Шаги — Teacher 13–30 ниже.

- **Задание = список конкретных слов**, а не ссылка на набор. Тогда одинаково работают целый
  набор, часть набора, несколько наборов и трудные слова. Слова, добавленные в набор после выдачи,
  задание не меняют.
- Поля: курс, слова (`card_ids`), тип (выучить / тест / повторить трудные), срок `due_at`,
  порог (по желанию), кому (вся группа / выбранные ученики), кто и когда создал.
- **Ученик:** есть задание → на главной **вместо «Урока дня»** карточка задания (несколько заданий —
  ближайшее по сроку). Нет задания → «Урок дня», как сейчас. Набор задания в списке выделен
  **янтарным** (токен `homework`, обе темы), под карточкой — «до: 15.11.2026 20:00».
- **Пуши ученику — два на задание:** при выдаче и вечером накануне срока, если ещё не сдано. Тихие
  часы соблюдаются.
- **Просрочено** → задание не исчезает, сдать можно позже, у учителя пометка «с опозданием».
- **Сдано** → снимок результата. Если потом слово откатилось, задание остаётся сданным.
- Учитель: экран сдачи (статусы, «Напомнить N», «Оценки в Excel»), карточка 1а на главной.
- **Что значит «сдано» — решено: вариант Б** (см. «Решения этапа 2»). Вариант А (каждое слово хотя
  бы раз верно) отклонён. Через неделю учитель видит «закреплено»: сколько слов дошли до «Знаю».
- Учителю при выдаче показать объём: «48 слов ≈ 10 сессий ≈ 70 мин» и предложить разбить на части.

### Решения этапа 2 (12.11.2026)

1. **«Сдано» — вариант Б:** слово задания засчитано, когда ученик прошёл его во всех этапах
   **законченной** сессии «Изучить» / «Повторить». Слова, которые в момент выдачи уже на «Знаю»
   (шаг ≥ 3), засчитываются сразу. Не считаются: свободная практика, мини-игры, живой тест, брошенная
   сессия. Задание сдано, когда засчитаны все слова → снимок (дата, «с опозданием», оценка).
   «Знаю» за одну сессию недостижимо (шаг растёт только по сроку: 1 → 3 → 7 дней), поэтому «Знаю»
   показываем отдельно как «закреплено», а не как условие сдачи. Дневной лимит новых слов на слова
   задания не действует.
2. **Кнопки следующих этапов не убираем.** «Проверить на уроке» (1а), «Пройти тест» и «Повторить
   трудные» (11) остаются в макете и свёрстаны в коде, но спрятаны за флагом
   `TEACHER_LESSON_PREP_ENABLED` до этапа 3: кнопка без действия в рабочей сборке не видна.
3. **Срок в окне «Новое задание» (макет 11):** в форме — карточка «до: Вс, 15.11.2026 20:00 ·
   через 3 дня». Нажатие на карточку открывает выбор даты и времени — барабан с анимацией, как
   в «Будильнике» iOS: дата · часы · минуты (шаг 5 мин). Над барабаном быстрые варианты «Завтра»,
   «Через 3 дня», «Через неделю» (+ «К уроку», если у курса есть расписание); по нажатию барабан
   докручивается сам. iOS — SwiftUI `DatePicker` `.wheel` (дата + время); Android и веб — системные
   окна выбора даты и времени. По умолчанию — через 3 дня, 20:00. Макет не перерисовываем,
   делаем при реализации.

4. **Оценка и порог (решение 12.11.2026).** Оценка — доля слов задания, которые в **последней**
   законченной сессии с этим словом были отвечены верно с первой попытки (этапы, пишущие прогресс:
   Карточки, Тест, Собери слово). Учитель задаёт порог в окне 11: «Засчитывать от 80%» (60 / 70 /
   80 / 90 % или «без порога», по умолчанию 80 %). Все слова засчитаны, но оценка ниже порога →
   «в процессе» (как Кубат «48/48 · 70%» на макете 12). Чтобы поднять оценку, ученик проходит сессию
   «Повторить N трудных» по словам задания с ошибкой — новая запись по слову заменяет старую.
   Задание сдано = все слова засчитаны **и** оценка ≥ порога → снимок.
5. **Тип задания в этапе 2 — только «Выучить слова».** «Пройти тест» и «Повторить трудные» — решение 2.
6. **+20 алмазов за сданное задание (решение 12.11.2026).** Начисляет только сервер, в момент
   снимка сдачи, один раз на задание (`users.diamond`, как ежедневные награды). Сдано с опозданием —
   без алмазов (на У4 вместо «+20» — «с опозданием»).
7. **Пуш накануне срока идёт всегда** (кому не сдано); переключатель «Напомнить отстающим» (11)
   не делаем.
9. **Работа шагами 13–29 — без команды на каждый шаг** (разрешено 12.11.2026): коммит «Teacher N»
   в dev после type-check 0 / тестов / eslint, **без push**. Остановка — только при расхождении
   кода с планом; результат этапа показать целиком после Teacher 29. Swift (20, 23) — только `swiftc -parse`.
8. **Окна 11а «Выбор слов» и 12а «Кто не сдал»** — по макету (дорисованы 12.11.2026).
