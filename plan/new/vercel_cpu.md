## Что нашли (16.11.2026)

За 30 дней (16.10–15.11.2026) — **4 ч 3 мин** Fluid Active CPU, почти всё проект `ai-app`.
До 28.10 ~3–4 мин в день, с 29–30.10 ~8–17 мин, в среднем **~11–12 мин в день**.

### 1. Почти каждый запрос — холодный старт

В логах почти у каждого запроса стоит предупреждение `DEP0169` (`url.parse()`), а Node печатает его
один раз на новый процесс. Значит, при каждом открытии приложения стартует 10–15 новых процессов сразу.
Пример, 16.11 в 02:57:43: одновременно `/api/data` ×5, `/api/progress` ×2, `/api/push`, `/api/library`,
`/api/books`, `/api/teacher`, а через 10 с `/api/ai` ×4. При каждом старте функция заново загружает
свои библиотеки — это чистый расход CPU.

### 2. Три функции при каждом старте загружают тяжёлые библиотеки, которые им почти не нужны

CPU на загрузку модуля, локально на Mac (на Vercel процессор медленнее):

| Функция | CPU на запуск | Что лишнее | Зачем на самом деле нужно |
|---|---|---|---|
| `/api/teacher` | **720 мс** | `pdfkit` (207 мс) + `exceljs` (282 мс) | только для скачивания PDF-отчёта или Excel с оценками |
| `/api/push` | **400 мс** | `exceljs` (282 мс) | ради одной маленькой `formatInZone` (`api/push/_arbiter.js:33` → `api/_homeworkExcel.js`) |
| `/api/ai` | **340 мс** | `@google/genai` (237 мс) | только для ИИ-импорта, а функция вызывается и для каждой озвучки слова (`fn=tts`) |
| `data`, `progress`, `library`, `books`, `test`, `share` | 80–120 мс | — | нормально |

`/api/teacher` открывается при любом заходе учителя, а cron-job.org каждые 15 минут запускает push —
и каждый раз грузятся Excel- и PDF-библиотеки, которыми почти никто не пользуется.

### 3. Почему расход вырос

- **29–30.10** — несколько выпусков подряд (1.6.5–1.6.9). Вероятно, при открытии приложения стало
  больше запросов или выросло число пользователей.
- **06.11** — озвучка идёт через `/api/ai` (TTS 1), и каждое новое слово тянет за собой `@google/genai`.
- **12–13.11** — `exceljs` и `pdfkit` добавились в `/api/teacher` и `/api/push` (Teacher 22, 29, 54).

## Шаги

- [ ] **CPU 1 — cron-job.org раз в 30 минут (без кода).** Задача `Reminders` (`cron-reminders`):
  `*/30` вместо `*/15`. Минус 48 холодных стартов push в сутки. Напоминания приходят с точностью
  до 30 минут: пропущенный слот подхватывает следующий запуск.
  *С Pro необязательно — решить, нужна ли точность 15 минут.* Делается вручную в cron-job.org, кода нет.

- [x] **CPU 2 — ленивая загрузка тяжёлых библиотек.** Поведение приложения не меняется.
  - ✅ Сделано 16.11.2026 (в `dev`). CPU на холодный старт, локально, медиана из 3:

    | Функция | Было | Стало |
    |---|---|---|
    | `api/teacher.js` | 720 мс | **181 мс** (ещё и `push.js` с firebase-admin — лениво в `roster.js`, `homework.js`) |
    | `api/push.js` | 400 мс | **194 мс** |
    | `api/ai.js` + озвучка (`tts`) | 340 мс | **69 мс** |

  - Jest не умел `import()` («without --experimental-vm-modules»): в `babel.config.cjs` для `env.test`
    добавлен `@babel/plugin-transform-dynamic-import` (devDependency). Тест серии считал пуши по ошибке
    этого импорта — теперь у него заглушка `push.js`.
  - `pdfkit` и `exceljs` — через `await import()` только внутри скачивания PDF/Excel
    (`api/_handlers/teacher/reports.js`, `api/_handlers/teacher/homework.js`).
  - `formatInZone` (и `DEFAULT_TIMEZONE`) — в маленький отдельный файл без `exceljs`; push и учительские
    ручки берут его оттуда.
  - `api/ai.js` загружает только нужный модуль по `fn` (озвучка без `@google/genai`).
  - Проверка: замер CPU на загрузку модуля до/после, тесты `api/__tests__`, staging.
  - Ожидание: запуск `teacher` примерно в 3 раза дешевле, `push` и озвучка — в 2–3 раза;
    всего минус ~30–45% расхода.

  (Usage) и Observability → Vercel Functions (на Pro видно расход по функциям). Ориентир — меньше

- [x] **CPU 4 — меньше параллельных запусков** (сделано 16.11.2026, по команде — не дожидаясь CPU 3):
  - ✅ Озвучка: `prefetchSpeech` (`src/utils/speech.ts`) синтезирует слова **по очереди**, а не все
    разом. Это и были 4 одновременных `POST /api/ai` — каждый поднимал свой процесс. Нажатие на динамик
    очередь не ждёт. Нужен выпуск приложения (клиентская правка).
  - ✅ Проверено: `data?action=news` и `data?action=app-version` уже кэшируются CDN
    (`s-maxage`), функцию не запускают — менять нечего.
  - ⏸ Остальные запросы при запуске (`bootstrap` и личные данные) — с авторизацией, на CDN не
    кэшируются. Объединять их — менять API и ждать, пока старые версии уйдут (release_safety).
    Делать, только если CPU 3 покажет, что нужно.
  - ⏸ Push-cron с Vercel не переносим: с Pro это экономия ~$0,1 в месяц, а перенос — риск запустить
    рассылку в двух местах сразу. Vercel Cron на Pro можно поставить вместо cron-job.org отдельным
    решением (ради надёжности, не CPU).

## Что не делаем

- Пинговать функции, чтобы держать их «тёплыми»: при одновременных запросах Vercel всё равно запускает
  новые процессы, а пинги сами тратят CPU.
- Второй бесплатный аккаунт — нарушает правила Vercel (и после перехода на Pro не нужен).
