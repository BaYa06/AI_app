# План: живой экзамен (алгоритм + знание учеников)

Цель — учитель проводит во Flashly **настоящий экзамен с оценкой**, которой можно доверять:
честный подбор слов, несколько форматов вопросов, понятные итоги «кто что знает», оценка по
100-балльной шкале, разбор ошибок у ученика. Запрос пришёл от учителей 17.11.2026: «хотим
довериться приложению полностью, точно видеть, кто учил, а кто нет, и ставить оценки».

**Две опоры, на которых строим всё остальное:**
1. **Алгоритм сборки экзамена** — обычный код, без ИИ: подбор слов, форматы, неверные варианты,
   пропуски в предложениях, проверка ответов. Предсказуемый и объяснимый.
2. **Знание учеников** — у нас есть история повторений каждого ученика по каждому слову
   (`review_log`, `card_progress`, `answers`). Ни Kahoot, ни Google Forms этого не знают.
   Используем при подборе слов (сложность) и в итогах (как ученик готовился).

Шаг = коммит «LiveExam N». Отмечать ✅ по мере выполнения. **Код — только после подтверждения
плана.** Работаем в `dev`, база — только staging (см. память «Только dev и staging»).

Макет (холст, 3 ряда экранов): https://claude.ai/artifact/WcVmpv2d9s4DpNM2D5LKmx
- ряд 1 — учитель: создание → «Собираем экзамен» → превью → идёт экзамен → итоги → карточка ученика;
- ряд 2 — ученик: выбор, письмо, «собери слово», пары, результат;
- ряд 3 — книга «Academic words» (слово ↔ определение): превью, определение → слово, вставь слово,
  пары в раскладке «слова сверху», «собери» длинного слова.
Цифры и имена в макете вымышлены. **Если план и макет расходятся, верен план.**

## Решения пользователя (не пересматривать без него)

- **Слова у всех одинаковые, порядок у каждого свой** — чтобы нельзя было списать у соседа.
  Внутри вопроса тоже свой порядок: варианты, буквы, колонки пар.
- **Шкала оценки — 100 баллов.**
- **Форматы:** выбор, письменный ответ, «собери слово», «соедини пары» (+ «вставь слово в
  предложение» для наборов с примерами).
- **Пары — одна механика на одном экране** (4 слова = 1 экран). При перемешивании блок двигается
  целиком; на карте вопросов занимает 4 номера подряд и подсвечивается целиком.
- **Подбор по сложности по умолчанию: ~33% лёгких, ~33% средних, ~33% сложных** — по данным
  повторений класса.
- **Рекомендованное время** считаем из выбранных форматов и показываем как «Советуем».
  Секунды на вопрос: выбор 13, письмо 28, «собери» 23, вставь 18, пара 8 (17.11.2026: прежние
  значения в реальности много, минус 7 с у каждого). Пример 20 слов → 7 минут.
- **Иконка «заменить слово» в превью** остаётся иконкой справа на строке слова, без меню
  и подсказки — учителю понятно.
- **Подозрительный вопрос — только через разбор** (17.11.2026, раздел E алгоритма): в итогах
  нет кнопки «Аннулировать», есть «Посмотреть вопрос» → экран с ответами по вариантам и
  именами, подсказками «почему могли ошибиться», выбором «Аннулировать / Засчитать ответ /
  Оставить» и расчётом «как изменятся баллы» до применения; решение можно отменить.
- **Карта вопросов сверху:** блоки с номерами, текущий — жёлтый, отвеченный — фиолетовый,
  без ответа — белый. Блоки 44×44 в одну строку с прокруткой вбок (меньше — не попасть пальцем).
- **Таймер становится красным, когда осталось ≤ 3 минут.**
- **Итоги «Ученики»** — карточка на ученика: имя, балл, полоска, «Верно: N · Ошибки: N ·
  Опечатка: N · Нет ответа: N» (нули не показываем). Матрицу «ученик × слово» не делаем.
- **В движке экзамена ИИ не используется.** ИИ допустим только как разовая подготовка карточек
  (примеры предложений, часть речи) с сохранением результата и правкой учителем — отдельно, позже.
- **Экран «Собираем экзамен»** показывает настоящие шаги алгоритма с настоящими цифрами.
  Сборка занимает < 1 с; пауза ~300 мс на шаг только чтобы шаги успели прочитаться, не больше.

## Алгоритм (опора 1)

Весь движок — чистые функции в `api/_exam/` (без `sql`, без сети), с юнит-тестами в
`api/__tests__/exam*.test.js`. Обработчики только загружают данные и сохраняют результат.
Это важно ещё и потому, что `api/test.js` может переехать на VPS (plan/new/vps_backend.md).

### A. Подготовка карточек (заранее, при сохранении/импорте — не во время экзамена)

1. **Тип оборота набора** `card_sets.back_kind`: `translation | definition`, источник
   `back_kind_source`: `auto | manual`. Правило по порядку:
   - алфавит лицевой и оборотной стороны разный (латиница ↔ кириллица) → `translation`,
     что бы ни было в `language_from/to`;
   - алфавит одинаковый: языки набора разные → `translation`, одинаковые → `definition`;
   - официальные книги — задаём явно при импорте (`scripts/import-book.ts`);
   - учитель может поменять в настройках набора («определено автоматически · изменить»).
   Считается по большинству карточек набора.
2. **Часть речи** `cards.pos_guess` (`verb | noun | adj | null`) — только для английских
   определений: «to …» → verb, «a/an/the …» → noun, иначе adj. Для переводов — `null`
   (позже можно заполнить ИИ при импорте). Существующий `word_type` не трогаем.
3. **Пропуск в предложении** (`cards.gap_text`, `gap_answer`, `gap_kind`) из `example`:
   - слово целиком (`\mслово\M`, без учёта регистра) → `gap_kind='exact'`;
   - слово с окончанием: ищем токен, начинающийся с основы (для `-e`/`-y` — без последней
     буквы) → `gap_kind='ed' | 's' | 'es' | 'ies' | 'ing' | 'doubled'`, `gap_answer` = токен
     **из самого предложения**;
   - не найдено → `gap_kind=null`, слово в этот формат не попадает. Позже — список
     неправильных глаголов (~200) для forbade/knelt.
   - слово дважды в предложении — пропуск в обоих местах.
4. Пересчёт полей — при создании/правке карточки, при импорте книги и одноразовым скриптом
   для существующих карточек (`npm run exam:prepare -- --staging`).

### B. Сборка экзамена (create, < 1 с)

Вход: курс, наборы/юниты, число слов N, режим подбора (`difficulty | random | manual`),
доли форматов, «брать слова, которые класс не открывал» (по умолчанию нет).

1. **Пул слов** — карточки выбранных наборов курса (`courseSetIdsSql`), без дублей по
   нормализованной лицевой стороне.
2. **Сложность слова для класса** — по ученикам курса (`course_members.role='student'`):
   доля учеников, у которых `card_progress.learning_step >= 3` («выучил»).
   `> 70%` — лёгкое, `30–70%` — среднее, `< 30%` — сложное. Слово, которое не открывал никто
   (нет строк в `review_log`) — «не изучено». Если данных нет совсем (новый курс) — запасная
   оценка: доля ошибок класса в прошлых экзаменах, иначе длина/число значений оборота, иначе
   случайно. В UI честно пишем, по чему считали. Пороги — константы в одном месте.
3. **Выбор слов** в режиме `difficulty`: по ⌈N/3⌉ из каждой группы; если в группе не хватает —
   добираем из соседней и показываем предупреждение на шаге сборки.
4. **Форматы.** Сначала определяем, в какие форматы слово **может** попасть (по ответу,
   который ученик даёт или собирает):
   - выбор — любое;
   - письмо — ответ ≤ 25 символов и ≤ 3 слов;
   - «собери» — ответ 3–14 букв, ≤ 2 слов (пробел — промежуток, не плитка);
     > 7 букв → плитки в 2 ряда;
   - пары — обе стороны ≤ 90 символов; для `definition` — раскладка «слова сверху,
     определения во всю ширину»;
   - вставь слово — есть `gap_kind`.
   Затем заполняем самые «узкие» форматы первыми («собери», вставь, пары), остальное — выбор.
   Не хватает подходящих слов — предупреждение «Для "Собери" подходит 2 слова, третье — в
   выбор», не молча.
5. **Направление:** `translation` — оба направления (по умолчанию поровну);
   `definition` — вопрос-определение, ответ-слово (обратное — только выбор и только если
   учитель включит). Письменный ответ всегда «напиши слово», никогда «напиши определение».
6. **Неверные варианты (3 штуки)** — из пула курса, затем книги: та же `pos_guess`
   (если известна), похожая длина, другая первая буква предпочтительнее, без совпадений с
   правильным после нормализации и без синонимов через запятую; с повышенным весом —
   частые ошибки класса на этом слове. Для «вставь слово» с изменённой формой варианты
   ставим в ту же форму по правилам (‑ed, ‑d после e, y→ied, ‑s/‑es); слова с удвоением
   согласной и неправильные глаголы в варианты **не берём**. Если вариантов < 3 — слово
   уходит в другой формат. **Варианты фиксируются при сборке** и одинаковы для всех; у
   ученика меняется только их порядок.
7. **Пары:** блоки по 3–5 пар (по умолчанию 4). Для 2 пар — нельзя (последнюю угадывают).
8. **Проверка на подсказки:** если пример слова X (вставь слово) содержит другое слово
   экзамена Y, а Y стоит в письме/«собери» — меняем формат одного из них.
9. **Рекомендованное время:** выбор 13 с, письмо 28 с, «собери» 23 с, пара 8 с, вставь 18 с
   (решение пользователя 17.11.2026: прежние 20/35/30/15/25 в реальности много, минус 7 с у каждого);
   сумма × 1,2, округление вверх до целой минуты. Пример: 8 выбор + 5 письмо + 3 собери + 4 пары =
   104 + 140 + 69 + 32 = 345 с × 1,2 = 414 с → **7 мин**. Константы; позже заменить средним временем
   из `test_answers.time_spent_sec`.
10. **Баллы:** 100 / число слов на слово (пара = слово). Итог округляем до целого.
    Учителю советуем N, на которое 100 делится (10, 20, 25), но не запрещаем 12.

### C. Выдача ученику (join)

- Порядок экранов — перемешивание **блоков** (пары — один блок) с зерном `participant_id`,
  внутри вопроса — варианты/буквы/колонки тем же зерном. Детерминированно: переподключение
  даёт тот же порядок.
- Номера на карте — по словам (1…N); блок пар занимает номера подряд.

### D. Проверка ответа

- Нормализация: регистр, пробелы по краям и двойные, ё→е, апостроф ’→', точка в конце;
  для `translation` — любой из вариантов через «,» / «;» засчитывается.
- Опечатка: расстояние Левенштейна 1 для ответов ≥ 5 букв → вердикт `typo` (0 баллов по
  умолчанию, учитель может засчитать).
- Вставь слово, письменный режим: базовая форма вместо нужной → `wrong_form` (0 баллов,
  учитель может засчитать).
- Вердикты: `correct | wrong | typo | wrong_form | none`.

### E. Подозрительный вопрос и его разбор (решение пользователя 17.11.2026)

Учитель **не аннулирует вслепую**: предупреждение в итогах ведёт на экран разбора вопроса
(макет: `Question.dc.html`), решение принимается только там. Всё считает код, без ИИ.

- **Когда предупреждаем:** ответили ≥ 4 ученика и ошиблись ≥ 70% из них. Кнопки в
  предупреждении: «Посмотреть вопрос» и «Оставить». Кнопки «Аннулировать» там нет.
- **Экран разбора:**
  1. Вопрос так, как его видели ученики. Варианты у всех одни, отличается только порядок,
     поэтому показываем один раз.
  2. Ответы по вариантам: число, полоска, имена. Для письма и «вставь слово» — сгруппированные
     ответы после нормализации («обычаи — 4: …»).
  3. «Почему могли ошибиться» — подсказки по правилам:
     - на повторениях (`review_log`) класс отвечал на слово верно ≥ 60%, а на экзамене разница
       ≥ 40 п.п. → «похоже, дело в вопросе, а не в знаниях»;
     - один неверный вариант собрал ≥ 50% ошибок → «вариант слишком близок к верному»;
     - один и тот же письменный ответ у ≥ 3 учеников → «возможно, это тоже верный перевод»,
       сразу предлагаем «Засчитать „…“»;
     - меньше половины класса повторяло слово → «класс почти не учил это слово» (тогда
       аннулирование не советуем: это честная ошибка).
  4. Действия (одно на выбор): **Аннулировать вопрос** (балл = верные / (N − аннулированные) ×
     100), **Засчитать „<ответ>“** (всем, у кого такой ответ или вариант), **Оставить как есть**.
  5. До применения — «Как изменятся баллы»: кто, было → стало, средний балл класса
     (сервер считает «вхолостую», ничего не сохраняя).
- После применения: пересчёт, запись в `test_score_log`, кнопка «Отменить» (обратная запись
  в журнал). Ученик в разборе видит пометку «вопрос аннулирован учителем» /
  «ответ засчитан учителем». Если результаты уже открыты ученикам — им приходит
  обновлённый балл без отдельного push.

## Знание учеников (опора 2)

- **Сложность слов** при сборке — пункт B2.
- **Подготовка ученика** в карточке ученика: число повторений слов экзамена и число дней
  с повторениями за 14 дней до экзамена (`review_log` по `card_id` экзамена), рядом — среднее
  по классу. Ученику открыто пишем, что учитель это видит (приватность).
- **Ошибки возвращаются в обучение:** после открытия результатов слова с ошибками у ученика
  становятся «нужно повторить» (сброс `card_progress.learning_step`/`next_review` по тем же
  правилам, что неверный ответ в повторении). «Домашка по ошибкам» — каждому его слова.
- **Подозрительные признаки** (только информация): все ответы быстрее 2 с; высокий балл без
  единого повторения; выходы из приложения.

## Модель данных (миграция `055_live_exam.sql` + блок в `api/_db-init.js`, `SCHEMA_VERSION = 'schema_055'`)

Миграции — через `api/_db-init.js` (как Center 1), текст дублируем в `database/migrations/`.

- `card_sets`: `back_kind TEXT CHECK (back_kind IN ('translation','definition'))`,
  `back_kind_source TEXT DEFAULT 'auto'`.
- `cards`: `pos_guess VARCHAR(8)`, `gap_text TEXT`, `gap_answer TEXT`, `gap_kind VARCHAR(10)`.
- `test_sessions`: `engine SMALLINT NOT NULL DEFAULT 1`, `config JSONB` (доли форматов, режим
  подбора, пороги, шкала), `duration_sec INT`, `paused_at TIMESTAMPTZ`,
  `paused_total_sec INT DEFAULT 0`, `reveal_mode VARCHAR(12)` (`on_submit | teacher`),
  `results_released_at TIMESTAMPTZ`.
- **новая** `test_items` — состав экзамена, общий для всех: `id`, `session_id`, `card_id`,
  `block_id` (у пар общий), `format` (`choice | write | scramble | match | gap`),
  `direction`, `prompt`, `answer`, `options JSONB`, `difficulty` (`easy | mid | hard | unstudied`),
  `points NUMERIC(5,2)`, `voided BOOLEAN DEFAULT false`, `sort_key INT`.
- `test_participants`: `question_order` хранит id блоков; `extra_sec INT DEFAULT 0`,
  `submitted_at TIMESTAMPTZ`, `score_override SMALLINT`, `score_comment TEXT`,
  `retake_of UUID` (пересдача).
- `test_answers`: `item_id UUID`, `verdict VARCHAR(10)`, `accepted BOOLEAN` (засчитал учитель),
  `points NUMERIC(5,2)`, `updated_at`. В движке 2 ответ можно менять до сдачи (UPSERT).
- **новая** `test_score_log` — кто, когда, что поменял (засчитал ответ, аннулировал вопрос,
  изменил балл, комментарий).

## API (`api/test.js`, новые action; старые не меняем)

| action | кто | что |
|---|---|---|
| `exam-build` | учитель | собрать и **сохранить черновик** (`status='draft'`, сделано так 18.11.2026: превью и замена работают с тем же составом, клиент состав обратно не шлёт): состав, шаги сборки с цифрами, предупреждения, рекомендуемое время |
| `exam-draft` | учитель | превью уже собранного черновика (повторное открытие) |
| `exam-create` | учитель | открыть черновик: код, `status='waiting'` (дальше `start` — как у теста) |
| `exam-replace-item` | учитель | заменить слово в черновике/до старта |
| `join` | ученик | как сейчас + `features: [...]` клиента; для `engine=2` без нужных возможностей → `426 { update: true }` |
| `exam-state` | ученик | все экраны ученика в его порядке (без ответов), его ответы, `deadline` |
| `exam-answer` | ученик | UPSERT ответа, **без правильного ответа в ответе**; после `deadline` → 409 |
| `exam-submit` | ученик | сдать; `reveal_mode='on_submit'` → вернуть разбор |
| `exam-pause` / `exam-extra-time` | учитель | пауза для всех / +N минут ученику |
| `exam-results` | учитель | итоги: карточки учеников со счётчиками вердиктов, вкладка «Слова», подозрительные признаки |
| `exam-question` | учитель | разбор одного вопроса: ответы по вариантам с именами, подсказки «почему ошиблись», расчёт «как изменятся баллы» для каждого действия (без сохранения) |
| `exam-decide` | учитель | решение по вопросу `void / accept (answer) / keep` → пересчёт, запись в `test_score_log` (вместо отдельных exam-accept / exam-void) |
| `exam-override` | учитель | изменить балл с комментарием (null — вернуть посчитанный) → журнал |
| `exam-undo` | учитель | отменить решение из журнала |
| `exam-release` | учитель | открыть результаты ученикам (push и «ошибки в повторения» — LiveExam 20) |
| `exam-my` | ученик | история экзаменов и разбор |
| `exam-homework` | учитель | домашка по ошибкам (через `api/_handlers/teacher/homework.js`) |

`deadline` = `started_at + duration_sec + paused_total_sec + extra_sec` — считает **сервер**.
Ответ после срока + 5 с → 409. Попытки с истёкшим сроком и сама сессия (через 60 с после
самого позднего срока) завершаются лениво — в `exam-state`, `exam-results`, `monitor`.

**Совместимость внутри сервера:** `question_order` участника — id слов в его порядке,
`answer_count` / `correct_count` ведутся по вердиктам. Поэтому монитор, контроль выхода,
`finish`, `results` и `history` движка 1 работают с экзаменом без изменений, и их формула
балла совпадает с баллом движка, пока учитель ничего не аннулировал/не засчитал (после —
`recomputeScores` пишет баллы в `test_participants.score`). Старое «автозавершение по времени
на вопрос» экзамены пропускает (`engine === 2`).

Проверка всего пути на staging: `npm run exam:check` → `scripts/check-exam-flow.ts`
(33 проверки, создаёт и удаляет данные EXAM-CHECK).

## Совместимость версий (plan/new/release_safety.md)

- Старые версии ученика не знают новых форматов → `join` для `engine=2` требует `features`;
  без них — ответ «обновите приложение» (экран из plan/done/app_update_prompt.md).
- Старые версии учителя видят экзамены `engine=2` в истории (поля `avgScore`, `setTitle`
  заполняем как раньше), но открывать итоги движка 2 не умеют → показываем «обновите».
- Старый тест (`engine=1`) не меняется ни в одной строке логики.

## Открытые вопросы (решает пользователь)

1. Блок пар на карте — 4 отдельных номера (как в макете) или **один широкий блок «6–9 · 2/4»**
   (предложено, не подтверждено).
2. Можно ли несколько блоков пар в одном экзамене (предложено: да, блок 3–5 пар).
3. Опечатка и неверная форма — 0 баллов с правом «засчитать» (предложено) или половина баллов.
4. Веса форматов (пары и «собери» легче) — сейчас все вопросы равны.
5. Пороги сложности 70% / 30% и секунды на формат — проверить на реальных классах.
6. Асинхронный экзамен (окно «с 18:00 до 21:00») и печатная версия — не в этом плане.
7. Показывать ли «подготовку» ученику самому и можно ли учителю её скрыть.
8. Входит ли расширенный экзамен в платный тариф для учителей/центров.

## Чего не делаем

- ИИ во время сборки, проверки или выставления оценки.
- Общий конструктор тестов с вопросами любого типа (картинки, свои вопросы) — не наша сила.
- Матрицу «ученик × слово» в итогах (заменена карточками учеников).
- Изменения в старом тесте и разминке (`engine=1`).
- Обещание «списать невозможно»: честно говорим «объективная картина + данные о подготовке».
