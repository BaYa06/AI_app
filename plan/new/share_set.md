# Поделиться набором по ссылке

Пользователь жмёт «Поделиться» в наборе → отправляет ссылку в любой мессенджер. Получатель:
- **есть приложение (iOS)** → ссылка сразу открывает экран-превью набора с кнопкой «Добавить все карточки»;
- **нет приложения (iOS)** → страница-превью в браузере → App Store;
- **Android** (приложения в Google Play нет) → страница-превью → веб-версия Flashly, там то же превью и «Добавить».

Шаг = коммит «Share N». Отмечать ✅ по мере выполнения.

---

## Решения (30.10.2026)

1. **Копия, а не подписка.** «Добавить» создаёт у получателя свою копию набора (как импорт из
   библиотеки). Правки автора после этого копию не меняют. Прогресс (SRS) не копируется.
   Ссылка всегда показывает **текущую** версию набора автора на момент открытия.
2. **Ссылка — случайный код, а не id набора.** `https://<домен>/s/<code>`, code — 10 символов
   base62 (перебором не найти). Один код на набор: повторное «Поделиться» отдаёт ту же ссылку.
   Автор может **закрыть доступ** — ссылка перестаёт работать; новое «Поделиться» создаст новый код.
3. **Не публично.** Набор по ссылке не попадает в библиотеку и поиск, его видит только тот,
   у кого есть ссылка. Библиотека остаётся только для админов (plan/done/community_library.md).
4. **Превью без входа, добавление — со входом.** Превью (название, языки, число карточек,
   первые 20 карточек, имя автора) открывается без аккаунта. «Добавить» требует вход —
   гостевой (anonymous) тоже подходит. Новичок проходит вход/онбординг, после чего набор
   добавляется автоматически (как `pendingInviteToken` для приглашений в курс).
5. **Повторное добавление** → «Набор уже у вас» + «Открыть». Свою же ссылку автор открывает
   как свой набор (и может добавить копию в другой свой курс).
5а. **Имя автора показываем** на превью и на странице в браузере.
5б. **Выбор курса у всех**: студент и учитель выбирают, в какой свой курс добавить. Если в курсе есть ученики — набор видят все они.
6. **Только текст.** Копируем `front`, `back`, `example`. `image_url`/`audio_url` не копируем
   (сейчас не используются; если появятся — отдельное решение, чтобы удаление у автора не ломало копии).
7. **Лимит**: наборы до 2000 карточек; превью отдаёт максимум 20.

## Слабые места и как закрываем

### 1. App Review 1.2 (контент пользователей) — главный риск
Библиотеку уже отключали по 1.2. Набор по ссылке — тоже контент одного пользователя, который
видит другой. Личная ссылка (как отправить файл) обычно проходит, но Apple может спросить про
модерацию. Закрываем заранее минимальным набором 1.2:
- на превью «…» → **«Пожаловаться»** (причина) → жалоба в админку, набор сразу скрывается у пожаловавшегося;
- **«Заблокировать автора»** — его ссылки у этого пользователя больше не открываются;
- админ в admin.html видит жалобы и может **закрыть ссылку** любого набора;
- `terms.html`: раздел о наборах по ссылке, нулевая терпимость к оскорбительному контенту;
- Review Notes: «Sets can be shared only via private link, they are not listed publicly. Recipients can report a set or block its author.»

### 2. Нет отложенной ссылки (deferred deep link)
Если приложения нет: App Store → установка → первый запуск — **iOS не передаёт ссылку**.
Firebase Dynamic Links закрыты (08.2025), Branch — платно и лишний SDK. Решение без SDK:
- страница-превью: «Установите Flashly и **нажмите ссылку ещё раз**» (+ кнопка «Скопировать ссылку»);
- в приложении: на главной/в «Добавить набор» пункт **«Вставить ссылку на набор»** — читает
  буфер только по нажатию (без системного запроса «Разрешить вставку» при запуске).
- Сервер не угадывает пользователя по IP — ненадёжно и спорно для приватности.

### 3. Старые версии приложения
Если сразу добавить `/s/*` в apple-app-site-association, iOS откроет ссылку в **старой** версии
приложения, которая её не понимает → пользователь попадёт на главную без набора. Поэтому:
- сначала выходит сборка, умеющая `/s/<code>` и `flashly://share/<code>`;
- до этого ссылка открывает страницу-превью в Safari (кнопка «Открыть в приложении» через `flashly://share/<code>`);
- `/s/*` добавляем в AASA **после** того, как новая версия разошлась (поэтапный выпуск 7 дней + ~1 неделя).

### 4. Ссылка не всегда открывает приложение
Universal Link не срабатывает, если ссылку вставили в адресную строку Safari, и во встроенных
браузерах (Instagram, иногда Telegram). Поэтому страница-превью — полноценная: превью,
кнопка «Открыть в приложении» (`flashly://share/<code>`), App Store, веб-версия.
Smart App Banner: в `api/join.js` сейчас `app-id=` пустой — нужен ID приложения в App Store.

### 5. Домен
Ссылки будут вида `ai-app-seven-zeta.vercel.app/s/…` — выглядит как подделка, в мессенджерах
меньше доверия. Но ждать покупки домена не нужно:
- **Решение:** запускаемся на текущем домене. Он не исчезнет, пока жив проект Vercel (на нём же
  весь API), поэтому отправленные ссылки не сломаются никогда.
- Домен ссылок — одна константа `SHARE_ORIGIN` (src/config) и переменная `SHARE_ORIGIN` на сервере;
  приложение и сервер разбирают ссылки **любого** из известных доменов.
- Когда купим свой домен (например, `flashly.app`): подключить в Vercel, добавить
  `applinks:<домен>` в entitlements (это новая сборка) и тот же AASA. Только после выхода
  этой сборки переключить `SHARE_ORIGIN` — новые ссылки пойдут на новый домен, старые продолжат работать.

### 6. Лимит функций Vercel
Сейчас 10 функций в `api/`. Новая `api/share.js` (страница-превью + JSON) → 11. На Hobby
предел 12 — запас один. Если тесно — действия в `api/library.js`, а страницу в `api/join.js`.

### 7. Нагрузка и злоупотребления
Превью без входа — публичный эндпоинт: кэш на CDN 60 с (`s-maxage`), ограничение импортов
(не больше 30 добавлений в час на пользователя). Импорт — **одним SQL-запросом** (как
`importSet` в api/library.js), без цикла по карточкам с клиента.

### 8. Стартовый набор новичка
plan/new/new_user_activation.md кладёт новичку стартовый набор. Пришёл по ссылке — набор
у него уже есть: **стартовый не создаём**, урок дня строится из добавленного.

## Шаги

### Share 1 — сервер: таблицы и API ✅
Совместимость по plan/new/release_safety.md (Release 2): только новые таблицы.
- `_db-init.js`:
  - `set_shares (code TEXT PK, set_id UUID → card_sets ON DELETE CASCADE, owner_id UUID, created_at, disabled_at NULL, views INT DEFAULT 0, imports INT DEFAULT 0)`, уникальный индекс по `set_id` где `disabled_at IS NULL`;
  - `set_share_imports (user_id, code, course_id NULL, set_id_created, created_at, UNIQUE NULLS NOT DISTINCT (user_id, code, course_id))`;
  - `set_share_reports (id, code, reporter_id, reason, created_at, resolved_at)`;
  - `user_blocks (user_id, blocked_user_id, created_at, PK(user_id, blocked_user_id))`.
- `api/share.js`, действия:
  - `create` (вход, владелец набора) → `{ code, url }`; повторно — тот же код;
  - `disable` (владелец) → закрыть ссылку;
  - `preview` (без входа) → название, описание, языки, число карточек, 20 карточек, имя автора (`display_name`, без email), `alreadyImported`/`isOwner` если есть токен; 404 `not_found` / 410 `disabled` / `blocked`;

  - `preview` с токеном дополнительно отдаёт свои курсы пользователя (не ученические) для выбора «Куда добавить»;
  - `report`, `block`.
- `vercel.json` не меняли: `/api/share?action=…` идёт через общий rewrite `/api/(.*)`; `/s/:code` — в Share 2.
- Сделано (30.10.2026): миграция 034 (`api/_db-init.js`, `database/migrations/034_set_shares.sql`),
  `api/share.js` + действие `status` (ссылка своего набора для меню «Закрыть доступ»).
  Проверено на локальном Postgres: 42 сценария (права, превью 20 из N, копия без прогресса и медиа,
  повтор 409, двойной тап без дубля, свой/чужой курс, жалоба, блок, закрытие, удалённый набор).

### Share 2 — страница-превью в браузере ⬜
Серверный HTML в стиле `api/join.js`, но по брендбуку.
- OG-теги: «<Название> — 48 карточек · Flashly», чтобы в Telegram/WhatsApp было красивое превью.
- Список первых карточек, автор, языки.
- iOS: «Открыть в приложении» (`flashly://share/<code>`), «Скачать в App Store», подсказка «после установки нажмите ссылку ещё раз», «Скопировать ссылку».
- Android и компьютер: «Открыть в Flashly» → веб-приложение `/?share=<code>`.
- Ошибки: ссылка закрыта / набор удалён — понятный текст и кнопка «Открыть Flashly».

### Share 3 — приложение: кнопка «Поделиться» ⬜
- `SetDetailScreen`: кнопка «Поделиться» (иконка Share из lucide) → `create` → системное меню `Share.share({ message })`.
- Текст сообщения (WhatsApp, Telegram, SMS и т.д.):
  > Вот мой набор «<Название>» — <N> карточек 📚 Давай учить вместе во Flashly!
  > <ссылка>
  - Ссылку кладём **внутрь `message`**, а не в отдельный `url`: на iOS при `url` + `message`
    WhatsApp и часть приложений берут только ссылку и теряют текст.
  - Какое приложение выбрал человек, iOS сообщает только после отправки, поэтому текст один для всех.
  - Текст на языке интерфейса автора (ru/en/…), через i18n.
  - Превью ссылки в WhatsApp/Telegram даёт страница из Share 2 (OG-теги).
- В меню набора: «Закрыть доступ по ссылке» (если ссылка есть) с подтверждением.
- Пустой набор (0 карточек) — кнопка неактивна.
- События analytics: `share_link_created`, `share_link_disabled`.

## Проверка в TestFlight
1. Автор: «Поделиться» → ссылка в Telegram → превью с названием и числом карточек.
2. Студент со своими курсами: тап → «Куда добавить» → курс → набор в этом курсе. Учитель: курс с учениками → набор виден ученику.
3. Второй аккаунт с приложением: тап → превью в приложении → «Добавить все» → набор в списке, урок дня его видит. Повторный тап → «Набор уже у вас».
4. Без входа (новая установка): тап → страница → App Store → установка → тап ещё раз → превью → вход → набор добавлен, стартового набора нет.
5. Android-браузер: страница → «Открыть в Flashly» → веб → вход → набор добавлен.
6. Автор закрыл доступ → ссылка показывает «Ссылка больше не действует».
7. Жалоба → набор пропал у пожаловавшегося, жалоба видна в админке.
