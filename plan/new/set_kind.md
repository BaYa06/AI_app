# Тип набора: язык или предмет

У набора появляется обязательное поле «Тип»: **Язык** или **Предмет**. От типа зависит, что показывает
приложение: для предмета (история, география, ОРТ) нет языковых режимов, нет озвучки, а ИИ-импорт
делает карточки «вопрос → ответ» вместо слов с переводом. Мнемонику убираем из приложения совсем.

Шаг = коммит «Kind N». Отмечать ✅ по мере выполнения.

---

## Решения (02.11.2026)

1. **Поле обязательное, по умолчанию ничего не выбрано.** Набор нельзя сохранить без типа.
   Варианты с короткими пояснениями:
   - **Язык** — слова и фразы с переводом;
   - **Предмет** — история, география, ОРТ: вопрос → ответ.
2. **Пустой тип = язык.** У существующих наборов, наборов из старых версий и наборов книг тип пустой (`NULL`).
   Приложение ведёт себя с ними как сейчас, то есть все режимы на месте. Автоматически тип не проставляем:
   существующие наборы владелец размечает вручную. При открытии такого набора в редакторе поле пустое,
   и сохранить его можно только после выбора типа.
3. **Режимы для предмета:** Карточки, Тест, Пары. Скрыты: Собери слово, Аудио, Слово в контексте.
   «Урок дня» не меняется: он и так из Теста и Карточек (`src/services/lessonFlow.ts`).
4. **Озвучки для предмета нет:** ни кнопки, ни автопроизношения, ни предзагрузки.
5. **Мнемонику убираем везде**, для языков тоже: поле в наборе, переключатель в шторке режимов (RN и iOS).
6. **ИИ-импорт для предмета** — только цели «Вопрос-ответ» (по умолчанию) и «Термины», без автоперевода.
7. **Тип копируется вместе с набором:** по ссылке «Поделиться», из библиотеки, при публикации в библиотеку.

---

## Как работает пустое и смешанное

- `kind` в базе: `'language' | 'subject' | NULL`. В коде везде одна функция `isSubjectSet(set)`:
  `set.kind === 'subject'`. `NULL` и `'language'` дают одно и то же поведение.
- **Главная собирает карточки всего курса из разных наборов.** Языковые режимы там показываем, только
  если **все** наборы выборки не предметные. Озвучку решаем по набору каждой карточки, а не по первой карточке.
- Набор книги (официальный) — всегда язык, `kind` не трогаем.

## Слабые места и как закрываем

1. **Старые версии приложения** поле не знают. Сервер отдаёт его лишним полем (они его игнорируют),
   их наборы создаются с `NULL` = язык. `UPDATE` от старой версии не стирает тип: `COALESCE`, как у языков.
   Миграция только добавляет nullable-колонку (Release 2).
2. **Порядок выкладки:** сначала сервер (Kind 1) в main → Vercel, проверить текущую версию из App Store,
   потом сборка. Иначе новая версия отправит `kind`, а старый сервер его молча потеряет.
3. **Мнемоника хранится только локально** (на сервере её нет). Убираем интерфейс, поле в типах
   оставляем: у пользователей в памяти телефона она лежит и никому не мешает.
4. **Нативная шторка iOS** (`ios/FlashcardsApp/StudyModeSheet.swift`) сама рисует переключатели, поэтому
   переключатель мнемоники убираем и там. Набор режимов шторка уже берёт из JS (`games`), это без изменений.
5. **Повтор режима из итогов** (`StudyResults`, `nextMode`) запускает тот же режим, что только что прошли,
   то есть скрытый режим у предмета туда не попадёт. Виджеты и push открывают урок, а не режим (`widgetLinks.ts`).
6. **Устные тесты учителя (OralTest) не трогаем.** Устный ответ по истории осмыслен.

## Проверка в TestFlight

1. Новый набор: без выбора типа не сохраняется. Старый набор открывается с пустым типом и все режимы на месте.
2. Предмет: в шторке Карточки, Пары, Тест. Нет озвучки в Карточках и Тесте. «Урок дня» проходит.
3. Главная: курс только из языковых наборов — все режимы; есть хоть один предмет — без Собери слово и Аудио.
4. Мнемоники нет нигде: ни в наборе, ни в шторке (RN и нативная iOS).
5. ИИ-импорт в предметный набор: фото страницы учебника истории → карточки вопрос-ответ на языке страницы.
6. Поделиться и библиотека: у получателя тип тот же. Старая версия из App Store открывает и создаёт наборы как раньше.
