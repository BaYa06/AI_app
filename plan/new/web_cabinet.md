## Решения пользователя (не пересматривать без него)

- Веб-кабинет — отдельный раздел под ноутбук в том же репозитории; учитель входит тем же аккаунтом;
  там всё, что есть в телефоне, плюс функции «только веб».
- **Экзамен:** создаётся в вебе с теми же настройками, что `ExamSetupScreen` (5 форматов: выбор, письмо,
  собери, пары, вставь). Ученики сдают в приложении: вкладка «Тест» → 4-значный код (движок 2 живого экзамена,
  версия приложения ≥ 1.9.6). Режим «экзамен как домашнее задание» — **пока не делаем**.
- **ИИ-тест:** переключатель «Умные варианты (ИИ)» только в вебе: новые предложения для «вставь слово» и
  варианты по смыслу для «выбора». ИИ только готовит черновик, учитель правит каждый вопрос/вариант,
  баллы ставит код. Сомнительный вопрос нельзя молча открыть (окно подтверждения).
- **Проектор:** отдельное окно (код, инструкция, счётчик, только имена; для курсов младше 18 — без имён).
  Проблемы учеников видит только учитель в своём окне.
- **Тексты:** по брендбуку — «курс» (не «группа/класс»), обращение на «ты», без рода, иконки Lucide вместо символов.
- **Контраст:** чинили только в макетах; токены приложения не трогали.
- Не делаем: слайды, планы уроков, чат-ботов, публичную библиотеку квизов.

## Технические факты из анализа

- Веб = webpack + react-native-web (не Expo); навигации по адресам в вебе нет (`linking` только native,
  `src/navigation/AppNavigator.tsx`). Для кабинета нужен свой вход webpack и `linking`.
- Почти весь сервер уже есть: `api/test.js` (экзамен: exam-build/…/exam-release, `api/_exam/*`),
  `api/teacher.js` (курсы, расписание `get-schedule`, ученики, трудные слова, задания, отчёты),
  `api/books.js`. Опоздавшие могут войти, пока экзамен идёт; `exam-decide` засчитывает ответ всем с таким ответом.
- Нет на сервере: генерации вопросов ИИ и проверки «второго верного ответа», банка вопросов юнита,
  записи «ученик пытался войти со старой версией», журнала событий экзамена, вида задания «прочитать текст».
- Риски: шаг ИИ 15–30 с — генерацию делать через `api/ai.js` (maxDuration 300), а не в `api/test.js`;
  ИИ-эндпоинты `generate-examples`, `context`, `translate-words`, `extract-*` без авторизации;
  Supabase на Free (лимит одновременных подключений Realtime); живой экзамен ещё не проверен на устройстве.

Объём этого плана: **вход → каркас → обзор → курсы и ученики → экзамен целиком** (создание, ИИ-варианты,

## Главные решения по устройству (предложение, ждёт подтверждения)

1. **Отдельная точка входа, не телефонное приложение.** Новый `index.teach.jsx` + `public/teach.html` и второй
   `entry` в `webpack.config.cjs`. Кабинет **не** монтирует `App.tsx` / `AppNavigator`: там виджеты, push,
   Firebase, онбординги, табы — на ноутбуке не нужны и утяжеляют сборку. Это уже принятый подход:
   `/center` и `/admin` — отдельные страницы.
2. **Переиспользуем слой данных, не экраны.** Берём как есть: `supabaseClient`, `auth/session`, `api/client`,
   `services/exam.ts` (`ExamApi`), `services/neon/*`, токены из `src/constants/`, `utils/teacherApiErrors`,
   чистую логику (`screens/exam/examConfig.ts`, `examCsv.ts`, `examLobbyText.ts`). Экраны пишем новые,
   под ноутбук: код в `src/web/`. Телефонные `Exam*Screen.tsx` (8 тыс. строк с учебниками, жестами, safe-area)
   в вебе не открываем.
3. **Свой маленький роутер на History API** (`src/web/router.ts`, ~100 строк, без `react-router-dom`).
   Маршрутов около 15, нужны только путь, параметры, `navigate`, назад/вперёд и защита страниц.
   Новых зависимостей нет. (Если к этому плану добавится много вложенных маршрутов — вернуться к вопросу.)
4. **Один и тот же сервер.** Новые действия добавляем только в `api/ai.js` (ИИ) и точечно в `api/test.js` /
   `api/teacher.js`. Старые версии приложения новые действия не вызывают → совместимость
   (`plan/new/release_safety.md`) не ломается. Миграции — только по необходимости, сначала на staging.
5. **Проектор не ходит на сервер сам.** Окно проектора получает данные от окна учителя через
   `BroadcastChannel`. Так не растёт число запросов и подключений Realtime (Supabase Free), у окна проектора
   нет токена учителя, и оно не может «подсмотреть» лишнее. Закрыли окно учителя — проектор показывает «Ожидание».
6. **Опрос, а не Realtime, для монитора.** Как у `LiveTestScreen` (опрос раз в 4 с плюс события). В вебе
   начинаем с опроса `exam-results`/`monitor` раз в 3–4 с, пока вкладка видна (`document.visibilityState`);
   Realtime подключаем только если опроса не хватит. Один канал на вкладку, не на ученика.
7. **Права:** кабинет пускает только пользователя с ролью «учитель». Сервер всё равно проверяет владельца
   курса в каждом запросе (как сейчас в `api/_handlers/teacher/*`) — экран входа это не защита.
8. **Тексты по брендбуку:** «курс», на «ты», без рода, иконки Lucide (в вебе `lucide-react` не нужен — берём
   SVG-пути из `lucide-react-native` через `react-native-svg`, она уже в `webpack` alias-цепочке; если не
   соберётся — инлайн-SVG набор из 20–30 иконок в `src/web/ui/icons.tsx`).

## Открытые вопросы

- **Признак «курс младше 18».** Для проектора без имён. В коде курса такого поля нет (`api/_handlers/teacher/courses.js`).
  Варианты: (а) настройка курса «Ученики младше 18» (поле в `courses`, миграция) — **рекомендую**, выставляется при
  создании курса и в настройках; (б) по возрасту учеников (в профиле возраста нет). До решения проектор по умолчанию
  **без имён** (безопасный вариант).
- **Роль учителя.** Подтвердить, где её надёжно брать в вебе (профиль `users.role` или `check-owner`), и что делать
  с «гибридом» (учитель, у которого тоже есть свои наборы для учёбы): входит как учитель, свои наборы в этом плане не показываем.
- **Лимиты ИИ.** Сколько запросов `exam-smart` в час на учителя и какая модель (Gemini AI Studio — как в `ai_import.md`).
- **Общие компьютеры.** Учитель может войти в кабинет в классе: по умолчанию сессия — `sessionStorage` (закрыл вкладку —
  вышел)? Или стандартный `localStorage` с галочкой «Это мой компьютер»? **Рекомендую галочку** (по умолчанию выключена).

## Риски

| Риск | Что делаем |
|---|---|
| Supabase Free — лимит одновременных подключений Realtime | Опрос, а не Realtime; один канал на вкладку; проектор без своих запросов |
| ИИ-шаг 15–30 с упирается в `maxDuration` | Только `api/ai.js` (300 с), не `api/test.js`; индикатор «Готовим варианты» |
| ИИ-эндпоинты без авторизации | Закрываем для новых вызовов в Web 16; старые — отдельным шагом, с учётом старых версий |
| Живой экзамен не проверен на устройстве | Web 28: обязательный ручной проход до включения домена |
| Ошибка кода/баллов из-за ИИ | ИИ — только черновик; учитель правит каждый вопрос; баллы считает код; сомнительный вопрос — окно подтверждения |
| Общий компьютер: данные учеников в браузере | Без `localStorage`-кэша данных; сессия по галочке «Это мой компьютер» |
| Рост бандла основного приложения | Отдельный `entry`: кабинет и приложение не тянут код друг друга; проверить размер чанков после Web 1 |
| Дрейф расчёта «Советуем N мин» между телефоном и вебом | Общий чистый модуль `examConfig.ts` + тест на равенство цифр |
