# Мои обращения: история отзывов и ответы команды

Сейчас «Написать нам» и окно «Как тебе Flashly?» сохраняются в `app_feedback` и видны в админке,
но пользователь после отправки видит только «Спасибо!» — сообщение для него исчезает.
Он не знает, прочитали ли его, а ответить мы можем только по email.

Делаем: каждое обращение — переписка. Пользователь видит историю, статусы и наш ответ,
мы отвечаем из админки, на ответ приходит push.

Макет: https://claude.ai/artifact/WgL7eLSFHBzPs2bEjHEMq5

Шаг = коммит «Support N». Отмечать ✅ по мере выполнения.

---

## Решения (31.10.2026)

1. **Одна сущность — обращение.** Строка `app_feedback` = обращение (ветка). Первое сообщение
   остаётся в `app_feedback.message`, всё последующее (ответы команды и дописки пользователя) —
   в новой таблице `app_feedback_replies`.
2. **Окно оценки тоже попадает в историю.** Каждая отправка окна оценки создаёт обращение.
   - Ответ в одно касание («Нравится», проблем не было, без текста) — виден в истории,
     но **не** попадает в «Ждут ответа» в админке.
   - Есть проблема или текст — ждёт ответа так же, как «Написать нам».
   - «Пропустить» до выбора ответа ничего не создаёт (как сейчас).
3. **Статусы для пользователя:**
   - «Отправлено» — мы ещё не открыли;
   - «Прочитано» — ставится само, когда админ открывает обращение (кнопка «Прочитано» больше не нужна);
   - «Есть ответ» — последний ответ команды пользователь ещё не открыл; после открытия статус «Прочитано».
   Пользователь дописал → обращение снова «новое» в админке и попадает в «Ждут ответа».
4. **Статусы для админки:** `new` (ждёт ответа) → `read` → `answered` → `closed`.
   «Закрыть» — галочка при ответе; закрытое обращение, на которое пользователь дописал, снова `new`.
5. **Профиль.** Пункт «Написать нам» → «Мои обращения» с бейджем числа непрочитанных ответов.
   Внутри: кнопка «+ Написать нам» сверху и список обращений (новые сверху).
6. **После отправки «Написать нам»** открывается созданная переписка вместо экрана «Спасибо!».
7. **Push на ответ** — новый тип `support_reply`, транзакционный (без лимитов частоты),
   тап открывает переписку `flashly://support/<id>`. В админке галочка «Отправить push» (по умолчанию включена).
8. **Ответ видит только автор обращения.** Ничего публичного — это не контент пользователей
   (App Review 1.2 не затрагивается).
9. **Лимит дописок** — общий с `FEEDBACK_DAILY_LIMIT` (10 сообщений в день на пользователя).
10. **Шаблоны ответов** в админке («Исправим», «Уже исправлено», «Идея в плане») — только
    подставляют текст в поле, редактируются перед отправкой.

## Слабые места и как закрываем

### 1. Старые версии приложения (plan/new/release_safety.md)
- `submitFeedback` не меняется: старые версии продолжают отправлять отзывы как раньше,
  их обращения просто появятся в истории после обновления.
- Новые методы API только добавляются, старые не удаляются и не меняют ответ.
- **Push в старую версию:** приложение не знает `flashly://support/<id>` и откроет главную
  без ответа. Поэтому push `support_reply` уходит только на токены с `push_tokens.app_version`
  ≥ `SUPPORT_MIN_APP_VERSION` (1.6.10). Старые версии версию не присылают — им push не уходит,
  ответ всё равно сохраняется, а в админке после отправки видно «push не ушёл: старая версия».
- Порядок выкладки: сначала API (Support 1–3), потом сборка приложения (Support 4–5).

### 2. Две админки
Список обращений отдают и `admin-server.mjs` (локальная, не в git), и `api/_admin.js` (через `api/data.js`,
страница `public/dashboard.html`). Переписка и ответы — только в `dashboard.html`; локальная остаётся как есть.

### 3. Удалённый пользователь
`app_feedback.user_id` — `ON DELETE CASCADE`, ответы удаляются вместе с обращением. В админке
обращения удалённых пользователей не остаются — как и сейчас.

### 4. Текст от пользователей
В админке весь текст выводится только через `esc()` (как сейчас). В приложении — обычный `Text`,
без ссылок-превью.

## Шаги

### Support 1 — база и API ✅
- Миграция `api/_db-init.js`:
  - `app_feedback_replies (id, feedback_id → app_feedback ON DELETE CASCADE, author 'user'|'admin',
    admin_id, message, created_at)` + индекс `(feedback_id, created_at)`;
  - в `app_feedback`: `read_at`, `last_message_at`, `last_admin_reply_at`, `user_seen_at`;
    статус допускает `answered`, `closed`.
- `api/data.js`:
  - `myFeedback` — список своих обращений: тип, категория/оценка, превью текста, статус для
    пользователя, есть ли непрочитанный ответ;
  - `feedbackThread` — одно своё обращение со всеми сообщениями; ставит `user_seen_at`;
  - `replyFeedback` — дописать в своё обращение (лимит, статус → `new`);
  - `feedbackUnreadCount` — число обращений с непрочитанным ответом (для бейджа);
  - `submitFeedback` с `returnId: true` возвращает `{ id }` созданного обращения. Без флага — по-прежнему
    `true`: старые версии сравнивают ответ строго с `true` и иначе показали бы ошибку отправки.
  - Дневной лимит 10 — общий для новых обращений и дописок (`assertFeedbackLimit`).
- Чужое обращение → 404 (неотличимо от несуществующего).
- Миграция 035 (`schema_035`), SQL — `database/migrations/035_feedback_replies.sql`.

### Support 2 — админка ✅
- Админка по ссылке — `public/dashboard.html` (в git, через `api/data.js`). Локальная `public/admin.html`
  + `admin-server.mjs` в `.gitignore` и не менялась: там по-прежнему старый список и кнопка «Прочитано».
- `api/_admin.js`: `getAdminFeedbackThread` (открытие ставит `read` и `read_at`, если было `new`),
  `replyAdminFeedback(adminId, id, message, { close })`, `closeAdminFeedback` («Закрыть без ответа»).
  В списке — `awaiting` (ждёт ответа), число сообщений в переписке, сортировка по последнему сообщению.
- `api/data.js`: `adminFeedbackThread`, `adminReplyFeedback`, `adminCloseFeedback` (только `is_admin`).
- `dashboard.html`: обращение раскрывается прямо в списке (вместо ветки справа — так работает и с телефона):
  переписка, «Прочитано · дата», прочитал ли пользователь ответ, шаблоны, поле ответа, «Закрыть обращение».
  Фильтр по умолчанию «Ждут ответа», счётчик «непрочитанных» → «ждут ответа». Кнопка «Прочитано» убрана.
- Автообновление раз в минуту не перерисовывает список, пока админ печатает; черновики ответов сохраняются.
- Галочка «Отправить push» — в Support 3.

### Support 3 — push ✅
- `api/push/_registry.js`: тип `support_reply` (category `support` — его не выключить отдельным
  переключателем, только общим; transactional; link `flashly://support/<id>?from=push`).
  Заголовок «Команда Flashly ответила», текст — первые 120 символов ответа.
  Флаг `anyText`: правило «число или имя в тексте» к нему не применяется — текст пишет человек.
  Флаг `minAppVersion` + `versionAtLeast()`.
- Миграция 036 (`schema_036`): `push_tokens.app_version`. `api/push.js` (subscribe) принимает `appVersion`.
- `api/push/_send.js`: для типов с `minAppVersion` берём только токены не старше, иначе статус `old_app`.
- Отправка из `adminReplyFeedback` по галочке «Отправить push» (по умолчанию включена). Ответ API
  содержит `push: { ok, reason }`, админка пишет под перепиской: отправлен / старая версия / нет токена /
  выключены уведомления / ночь — уйдёт утром (тихие часы, как у остальных пушей).

### Support 4 — экраны в приложении ✅
- **Подписка на push присылает `appVersion`** (натив — при каждом входе; веб — при новом токене или новой
  версии, `fcm_token_app_version` в localStorage). Без этого `support_reply` не дойдёт.
  **Версия сборки должна быть ≥ `SUPPORT_MIN_APP_VERSION` (1.6.10)**, иначе поменять константу в `_registry.js`.
- `src/services/feedback.ts`: типы `SupportTicket` / `SupportThread`, загрузка, ответ, счётчик;
  `NeonService`: `submitFeedbackForThread` (`returnId`), `myFeedback`, `feedbackThread`, `replyFeedback`,
  `feedbackUnreadCount`.
- `SupportListScreen` — «Мои обращения»: «Написать нам» сверху, карточки со статусом («Отправлено»,
  «Прочитано», «Есть ответ», «Закрыто»), непрочитанный ответ выделен; обновляется при возврате и потягиванием.
- `SupportThreadScreen` — переписка: свои сообщения справа, «Команда Flashly» слева, «Прочитано командой · дата»
  на своём месте, поле ответа внизу (лимит 429 → понятный текст). У оценки сверху — что ответили в окне.
- `FeedbackScreen` после отправки открывает созданную переписку (`navigation.replace`); если сервер
  ещё старый (вернул `true`) — прежний экран «Спасибо!».
- `ProfileScreen`: «Написать нам» → «Мои обращения» + бейдж (`feedbackUnreadCount` при фокусе).
- Deep link `flashly://support/<id>` (`widgetLinks.isNavigationUrl` + `linking.config`), тап по push.
  Открыли из push при холодном старте — «Назад» ведёт в «Мои обращения», оттуда в профиль.
- Веб: тап по push открывает главную (как у остальных пушей на вебе), ответ виден в «Моих обращениях».

### Support 5 — окно оценки
- `RatingPromptModal`: если отправлен текст или отмечены проблемы, в шаге «Спасибо» строка
  «Ответ придёт в “Мои обращения”» (окно не закрывается само, пока её не прочитали — кнопка «Готово»).
- Ответ в одно касание — как сейчас: «Спасибо за отзыв!» и окно закрывается само.
